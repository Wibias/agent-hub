# D12.3 Phase 11: read-only single Claim Evidence review across branches

Stacked on Draft #202. This opt-in local diagnostic is NOT a host
authentication, semantic conflict classifier, Claim promotion, or project-wide
policy implementation.

## Purpose

The project-wide Streamer Content scope inventory showed two active Claims
on the same non-main branch. They have declared user_direct primary Evidence
but have not been checked for semantic overlap with the confirmed full-E2E
quality assurance project rule.

This tool resolves exactly ONE project-scoped Claim by its opaque Claim ref.
The ref is the same ~c<12 hex> generated by Phase 10. It does not require
the hidden feature branch name to resolve the Claim; the sourceBranch argument
is only used to return a boolean for whether the Claim belongs to the caller's
source branch.

## Security

- SQLite is opened read-only in one BEGIN/ROLLBACK transaction.
- Reject unknown scope, missing tables, unresolved ref, hash collisions, and
  too many Claims to disambiguate (1000).
- A selected Claim requires a correctly bound primary claim_evidence link.
  Every linked source must exist, belong to the Claim's exact project/branch,
  and have normal sensitivity. Otherwise content is suppressed and review
  status is blocked. More than 50 sources also blocks content.
- Default output has only opaque refs, state/kind, source metadata, and
  explicit not-verified flags; no Claim text, Evidence, source path, branch
  name (except the caller's sourceBranch), raw IDs or timestamps.
- Optional --show-local-content reveals only the selected Claim's subject,
  predicate and value_text (each at most 1000 characters), and redacted
  Evidence excerpts (each at most 4000 characters). Truncation is flagged.
- CLI refuses content mode without an interactive TTY. No clipboard,
  file export, upload or logging feature is provided.
- Normal sensitivity classification is not proof the redacted excerpt is
  safe to share. Inspect locally before pasting into any conversation.
- Source authority user_direct is not a cryptographically authenticated
  human confirmation. No source body digest or immutable provenance is
  authenticated by this audit.
- No LLM interpretation, semantic conflict decision, project-scope rule
  inheritance, status update, import/export, or apply flag exists.

## Windows

Create a separate detached worktree from the existing Phase 10 checkout:

    $Previous = "$HOME\agent-hub-D12-3-cross-branch-inventory"
    $Next = "$HOME\agent-hub-D12-3-claim-review"
    if (-not (Test-Path $Previous)) { throw "Previous worktree missing" }
    if (Test-Path $Next) { throw "Destination already exists" }
    git -C $Previous fetch origin pull/REPLACE_PR/head
    if ($LASTEXITCODE -ne 0) { throw "Fetch failed" }
    git -C $Previous worktree add --detach $Next FETCH_HEAD
    if ($LASTEXITCODE -ne 0) { throw "Worktree creation failed" }

    $Db = if ($env:AGENT_HUB_MEMORY_DB) {
        $env:AGENT_HUB_MEMORY_DB
    } else {
        Join-Path $env:LOCALAPPDATA "agent-hub\memory.sqlite3"
    }
    if (-not (Test-Path $Db)) { throw "Memory database missing" }
    $Cli = Join-Path $Next "scripts\inspect-memory-cross-branch-claim-evidence.mjs"
    node $Cli --db-path $Db --project-id "github.com/Wibias/streamer-content" --source-branch main --claim-ref "~c8b37888bd75d"

To inspect the specific text in your own interactive terminal, append
--show-local-content to the same invocation. Review before sharing.
Repeat separately for the second Claim ref ~c9be7bfcbd72f.

No status value here approves a future promotion. Full manual review of
meaning and all project-wide Candidates/Proposals is still required for
the E2E QA rule. Production remains NO-GO; do not merge automatically.
