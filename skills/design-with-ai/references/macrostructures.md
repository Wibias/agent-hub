# Macrostructures - pick one before code

Structural variety is the skill's primary anti-slop weapon. Color and font
swaps without a different page shape still read as the same AI template.

**Diversification:** do not reuse the last stamped macrostructure in the
project or session. Prefer a different **group** (grid / document / poster /
product / proof).

State aloud before building: `Macrostructure: <name>`.

## Groups and picks

### Grid-led

| Name | Shape | Reach for when |
|---|---|---|
| **Bento** | Irregular modular blocks; size variation is the rhythm | Many features of unequal weight; product surface mosaic |
| **Catalogue** | Uniform inventory grid (SKUs, typefaces, swatches) | The offering *is* a set of variations |
| **Portfolio** | Filterable work cards; work is the product | Studios, agencies, case-study homes |

### Document-led

| Name | Shape | Reach for when |
|---|---|---|
| **Long Document** | Continuous prose; memo/journal energy; inline heads | Thought-leadership, essays, calm product philosophy |
| **Letter** | First-person, intimate, greeting; few buttons above fold | Founder notes, personal products, trust-first |
| **Index-First** | Page is a list of links; navigation as design | Directories, knowledge hubs, link-dense tools |

### Poster-led

| Name | Shape | Reach for when |
|---|---|---|
| **Marquee Hero** | Fold is one bold statement or visual; rest of page changes mode | Brand moments, launches, strong single claim |
| **Manifesto** | Polemical large type; belief before buy | Mission-driven, contrarian, category-creating |
| **Type Specimen** | Typeface *is* the design | Foundries, design systems selling type |
| **Specimen** | Numbered rails, huge display, asymmetric spans, hairline rules | **Only** explicit editorial / foundry briefs - never default |

### Product-led

| Name | Shape | Reach for when |
|---|---|---|
| **Workbench** | Real product UI / screenshots are primary content | Devtools, SaaS demos, "show don't tell" |
| **Feature Stack** | Sticky label pane + scroll-synced proof pane | Deep product tours, cinematic pacing |
| **Split Studio** | Diptych blocks alternating text/proof direction | Design-forward products, studio aesthetics |
| **Narrative Workflow** | Numbered stages over time (1→2→3) | Onboarding stories, process products |
| **Component Playground** | Interactive code + preview blocks | Libraries, docs, design-system marketing |

### Proof-led

| Name | Shape | Reach for when |
|---|---|---|
| **Stat-Led** | Giant number as hero; rest qualifies it | **Only with real metrics from the user** |
| **Quote-Led** | Pull-quote hero with real attribution | Strong social proof available |
| **Photographic** | Huge image per fold; text as annotation | Fashion, food, travel, physical craft |
| **Conversational FAQ** | Bold questions, short honest answers | Support-led, pricing anxiety, transparency |
| **Map / Diagram** | Spatial diagram organizes the page | Platforms, ecosystems, system products |

## Footer archetypes

Default **away** from Ft3 (4 columns Product/Company/Resources/Legal + social + copyright).

| Code | Pattern |
|---|---|
| Ft1 | Mast-headed brand close |
| Ft2 | Single inline rule + links |
| Ft3 | Index columns - **hubs/docs only** |
| Ft4 | Dense colophon |
| Ft5 | Statement (one line closes the page) |
| Ft6 | Letter close (" - name") |
| Ft7 | Newsletter-first |
| Ft8 | Marquee strip |

## SaaS section recipe (not a stamp)

When macro is Bento / Stat-Led / Workbench / Marquee **and** brief is B2B SaaS,
these sections should usually exist (how they look is macro-specific):

1. Hero (macro-specific) · 2. Proof / logos · 3. Features · 4. Testimonials
(real or omitted) · 5. Pricing with real numbers · 6. FAQ · 7. Final CTA · 8. Footer

Skip freely for non-SaaS (bakery, manifesto, letter, portfolio).

## How to pick under pressure

1. Match brief energy to a row above.
2. Exclude last stamped macro.
3. If vague: offer **three from different groups**, recommend one.
4. Never fall through to Specimen or 3-equal-card hero by reflex.
