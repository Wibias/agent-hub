# Signature moves - one memorable choice

A signature move is a **single committed decision** that makes the surface
belong to this product. Without it, correct spacing still reads as template.

## Rules

1. Name exactly one primary signature per page/app shell.
2. It must survive a grayscale test (structure/type), not only a color swap.
3. It must not fight the job (dashboard signatures ≠ marketing signatures).
4. Prefer structure, type, or interaction over decoration.
5. Document it in the stamp: `signature: <one line>`.

## Good signatures (examples - invent for the brief)

| Domain | Signature ideas |
|---|---|
| Editorial brand | Masthead + chapter rules + one outlier display face in two slots only |
| SaaS tool | Dense workbench hero with real UI, quiet chrome, mono metrics |
| Consumer | Soft card rhythm + one spring press language + illustrated empty states |
| Docs/OSS | Install block as hero, code-first proof, agent-readable headings |
| Luxury | Extreme whitespace, edge-aligned nav, statement footer |
| Data product | Tabular-first, mixed-size metrics (number large / unit small) |
| Local/service | Photographic folds, letter-close footer, no SaaS chrome |

## Weak "signatures" (reject)

- Random blob gradient
- Gradient text on the H1
- One purple accent on an otherwise Inter template
- Bento grid used because "everyone does bento"
- Glassmorphism without material meaning
- Custom cursor as the only personality

## Minimal with pops

Keep 90% quiet. One pop (accent section, metric, illustration, motion moment).
If everything pops, nothing does.

## Personality when no system exists

Default to refined minimalism **plus** one intentional personality choice
(accent, type treatment, empty state, divider language). Never pure template
neutrality.

## Second-order category check

After picking a signature, ask:

1. Could someone guess this aesthetic from the industry alone? → rework.
2. Could they guess it from industry + "not the usual SaaS cream"? → rework
 again until both answers are no.
