# Pricing Page Reference

Source: MengTo/Skills (https://github.com/MengTo/Skills), MIT License, Copyright (c) 2026 Meng To. Adapted 2026-07-09.

Design a pricing page that helps visitors choose and feel confident. The job is not to show prices -- it is to reduce uncertainty.

---

## Before You Start
Gather (ask if missing):
- What are you selling and who is it for? (category + ICP)
- What is the main value metric? (seat, usage, project, revenue)
- Plan names + prices (monthly/annual)
- Key limits per plan (3-6 that matter)
- What is the upgrade trigger?
- Top 3 reasons people do not buy today
- Security/compliance needs? (SOC2, GDPR)
- Can you offer: free trial, free plan, money-back, demo?
- Testimonials, logos, results, metrics
- Traffic context: homepage, feature pages, ads, comparison pages?

---

## Core Structure

### Above the fold (must-have)
- Clear value headline (what outcome, for whom)
- Monthly/annual toggle with savings callout
- 3-plan pricing table (most common) or 2-plan for simple products
- Primary CTA per plan with consistent verbs

### Below the fold (high leverage)
- Plan comparison (feature matrix or bullet list)
- FAQ (objection handling)
- Social proof near decision points
- Security / compliance / procurement section (if B2B)
- Final CTA + contact sales

---

## Layout Types

### A) Classic 3-card
Best when you have 3 natural tiers (Starter / Pro / Business) and pricing is simple.
Rules: 1 plan labeled Recommended; show "most popular" without overstatement.

### B) Value metric slider
Best when pricing scales with usage (seats, events, credits).
Rules: keep math obvious; set a safe default at the median customer.

### C) "Pick your path" (two columns)
Best when serving different audiences (Individuals vs Teams).
Rules: separate by persona first, then price.

### D) Enterprise last mile
Best when self-serve and sales-led paths coexist.
Rules: Enterprise section reads like procurement reassurance, not a feature list.

## High-Conversion Strategies

### Make the decision easy
- 3 plans max unless there is a strong reason for more.
- One recommended plan.
- Bullets describe outcomes, not internal feature names.

### Anchor value
- Annual toggle with "Save X%".
- Show "Starting at" only if pricing is genuinely variable.
- Avoid surprise fees.

### Reduce risk
Choose at least one: free trial, free plan, money-back guarantee, "Talk to sales" with a clear promise.

### Handle objections before they bounce
Most effective FAQ topics: "Can I cancel anytime?", "What happens if I hit limits?", "Do you offer discounts?", "Is this for freelancers/teams?", "Security / data / compliance".

### Provide a readable comparison
- Avoid huge spreadsheets.
- Group by: Core, Collaboration, Admin/Security, Support.
- Highlight what changes at each tier.

## Copywriting Templates

### Headlines
- "{Outcome} for {audience} -- without {pain}"
- "Plans that scale from {small} to {big}"
- "Start small. Upgrade when {trigger}."

### Plan description (2 lines)
- Line 1: who it's for.
- Line 2: what it unlocks.
Example: **Pro** -- For designers shipping weekly. Better components, faster iteration.

### CTA buttons
Rules: verbs that match the motion.
- "Start free trial"
- "Buy Pro"
- "Contact sales"
Keep CTAs consistent across plans.

### Feature bullets (write as outcomes)
- Avoid: "Unlimited projects"
- Prefer: "Ship unlimited client sites without extra fees"

## Pricing Table Checklist (UI)
- Visible monthly/annual toggle
- "Save X%" callout on annual
- Recommended plan styled subtly
- Key limits visible (3-6 max)
- Included items visible (3-6 max)
- Clear next step under each plan (trial/buy/contact)
- Link: "Compare plans" scrolls to matrix
- Mobile: table becomes stacked cards, not a horizontal scroll nightmare

## SEO + AEO

### SEO basics
- Title: "Pricing -- {Product}" + outcome keyword
- Meta: 1 sentence on value + 1 sentence on starting price
- Clean URL: `/pricing`
- Internal links from: homepage CTA, feature pages, comparison pages

### AEO (answer engines)
- FAQ answers: refund policy, trial length, cancellation, seat/usage definition, enterprise procurement
- Write FAQs in plain Q/A format
- Optional: FAQ schema if the stack supports it

---

## Common Pitfalls
- Too many plans (analysis paralysis)
- Features listed with no context (why they matter)
- Pricing hidden behind "Contact sales" for everything
- Switching value metric mid-page
- Over-designed table that harms readability

## Output Format

3. FAQ list (6-12 Q/A)
4. SEO/AEO (title + meta + FAQ schema suggestion)
5. Layout recommendation (A/B/C/D + why)
