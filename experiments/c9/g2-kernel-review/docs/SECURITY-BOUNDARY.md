# G2 native token and G345 binding security boundary

- Two OS identities are REQUIRED: Broker under LocalService user `S-1-5-19` plus enabled `AgentHubEG4528JournalBroker` service SID, without Scratch SID; client under LocalService user plus enabled `AgentHubD121417ScratchSvc` service SID, without Broker SID. Both have zero restricted SIDs. Broker token must be primary, pipe client token must be impersonation type at level `SecurityImpersonation` (=2).
- Run `ReadFile` synchronously, then `ImpersonateNamedPipeClient` immediately on the SAME OS THREAD. Capture client token with `OpenThreadToken`, query native SID/group/token data. No G3, G4, G5, target IO or logging while impersonated. `RevertToSelf` is mandatory and fatal on failure.
- `G2345PipeReview` is the only native G2-bound integration entrypoint. It does not trust caller-asserted token flags and sets them for `ReviewGate` only after successful OS identity checks.
- Service identities are exact values taken from the prior read-only broker's frozen `BrokerIdentity.cs`; they are NOT generated by the test process.
- The separate synthetic `ReviewGate.Evaluate` still exists only in CI; DO NOT use it as a production G2 authority. The new entrypoint also has a hard ephemeral-runner guard.
- The review runner cannot supply those service SIDs without installing/running services. Thus **negative tests are the only meaningful G2 service-identity outcome here**. No attempt to create services or local accounts. This is a blocker, not a reason to degrade the policy.
- No production read-only broker integration, SCM access, G2 positive attestation, handle-relative commit, external G4 immutable nonce, or G1-G7 security sign-off. G2 HOLD; Production NO-GO.
