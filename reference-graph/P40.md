# P40: new read-only Standard/Deep evidence path (default-off)

**Status:** Draft/review-only. Standard and Deep remain Legacy-only in production. No Graph activation or release approval.

## Why this increment exists

The 2026-11-08 P31 refresh-function receipt is lost. A later P7/P31 match cannot authenticate that earlier P33/P37 HTTP snapshot. Never invent or retroactively "recover" the old receipt.

The original P33 and P37 source files are protected by the #274 historical P35 reviewed-file manifest. **P40 does not modify or repin them.** Instead it adds a separately versioned read-only observation/evaluation path with an explicit new source method. A CI test MUST fail if old pinned P33/P37 content is changed; the historic lock stays intact.

## New source witness

`ops/p40-source-projection-witness.sql` is a single read-only PostgreSQL statement. Run only via an independently authenticated and authorized operator connection to project `vrznfnxzlxaavpqbzbzd`. It compares P7 eligible current-UTC candidates against published P31 candidates, including all metadata fields and primary_stratum from current_assets. It returns only count, legacy-ID-set SHA-256, mismatch counters and UTC observation/refresh timestamps. No raw rows, new functions, privileges, refresh operations or schema changes.

`p40-readonly-witness.mjs` validates the exact schema, target, date, counts, identity set, zero metadata/membership mismatches, a single refresh instant, maximum 15-minute witness age and 4-hour snapshot age. The witness JSON bytes MUST be separately pinned and attested by an authorized source; self-hashing it does not create independence.

## Two-stage live parity, kept separate from pinned P33/P37

`p40-readonly-parity.mjs` contains two explicitly **new** operator-only audit functions, neither wired to production routing:

1. **`auditP40ReadOnlyRecordParity`**: after verifying separately archived template, P27 baseline and P40 source witness bytes/hashes, perform a service-only, GET-only P30 read and verify exact refresh instant, current-day count, identity digest and P29 Standard/Deep record-order/coverage parity (48 cases). Return only a `reference-graph.p40-readonly-record-parity.v1` aggregate with a P33-v2-compatible **nested data contract** used later by the unchanged P34 comparator. This is NOT a claim that the original P33 implementation ran or the old P31 receipt was recovered.
2. **`auditP40ReadOnlyFullParity`**: require the stage-one aggregate's compact JSON SHA256 **pinned externally before the second HTTP request**. Read another current P30 snapshot, reject a different refresh timestamp or changed candidate metadata/content, and use the existing pinned P34 implementation to compare 48/48 record order, patterns and complete public JSON output over the **same candidates fetched inside this second stage**. Return only a versioned P40 aggregate. Do not call this existing P37; it is an alternative method which must be independently reviewed and explicitly accepted by P35's successor release policy.

The two live reads must see the **same `refreshed_at`** and must happen before the 15-minute witness freshness expires. If refresh or pin changes, collect new witness and re-freeze the evidence; never alter historical pins.

The complete external evidence packet needs: exact main/code SHA, project identity, legacy-source checkout SHA, independent raw byte hashes of P27 baseline and P34 public-output baseline, independently pinned P40 witness and stage-one result, stage-two P40 report, source authentication/time, live endpoint security and latency/error/fallback probes. The operator must keep `sb_secret_` on the trusted local server process, never in GitHub, stdout, logs, CLI arguments or browser.

**Current status:** The P40 witness SQL has been read-only executed successfully against dedicated Supabase, but that standalone observation is **not** a complete independent P33/P34/P37 release attestation.

## Standard/Deep shadow-only handoff

`p40-profile-shadow-handoff.mjs` runs P29 selection over already verified *offline* candidates, hydrates matching local records, and checks record and pattern order against untouched Legacy. It never accesses a network, writes usage or changes routing. P11 and `knowledge/design-references/scripts/query.mjs` remain unchanged, including P17 Quick activation and the `legacy` default.

A later separate, reviewed runtime integration still needs a cryptographically authenticated **versioned, profile-scoped activation authority**, trusted-server service-only transport, per-request record/pattern exactness and sanitized Legacy fallback, canary/kill-switch with p95 latency/error/quality budgets, rollback rehearsal and post-change monitoring. No such authority is created by this PR.

**NO-GO:** No production Standard/Deep route, Graph activation, database/cron write, migration, deployment, key publication or Windows task change. New independent same-snapshot P40 evidence and activation approval remain open in #275.

## Reproducible operator CLI (no writes)

Use `reference-graph/cli/p40-operator-readonly-audit.mjs` on the **trusted local operator host**. It never writes files, runs migrations, reads environment variables other than the isolated `P40_SUPABASE_SECRET_KEY`, or prints raw candidates or secrets. It fails closed with exit 2 and a generic error.

Create a **private local** manifest outside the repository, containing **independently archived** SHA256 hashes and paths (example below is not passing evidence):

```json
{
  "schema_version": "reference-graph.p40-operator-manifest.v1",
  "target_url": "https://vrznfnxzlxaavpqbzbzd.supabase.co/",
  "approved_record_report_sha256": null,
  "files": {
    "sourceWitness": { "path": "C:\\audit\\p40-witness.json", "sha256": "<64 lowercase hex>" },
    "baseline": { "path": "C:\\audit\\p27-baseline.json", "sha256": "<64 lowercase hex>" },
    "templates": { "path": "C:\\audit\\templates.json", "sha256": "<64 lowercase hex>" }
  }
}
```

Before running, load the dedicated project `sb_secret_` into `P40_SUPABASE_SECRET_KEY` **locally and securely**, never paste it into chat, GitHub, the manifest or a command-line argument.

```powershell
node .\reference-graph\cli\p40-operator-readonly-audit.mjs --stage record --manifest C:\audit\p40-manifest.json > C:\audit\p40-record.json
if ($LASTEXITCODE -ne 0) { throw "P40 record audit blocked" }
Get-FileHash C:\audit\p40-record.json -Algorithm SHA256
```

**Stop here.** An independent trusted reviewer/process must archive the P40 record aggregate and establish its digest *before* stage two. Amend `approved_record_report_sha256` in the manifest to that externally attested lowercase digest, and add the three pinned `files`: `records`, `patterns`, `publicBaseline` (same `path`/`sha256` shape). Complete the second request before the witness's 15-minute freshness window expires and before the P38 refresh changes the projection.

```powershell
node .\reference-graph\cli\p40-operator-readonly-audit.mjs --stage full --manifest C:\audit\p40-manifest.json > C:\audit\p40-full.json
if ($LASTEXITCODE -ne 0) { throw "P40 full audit blocked" }
Get-FileHash C:\audit\p40-full.json -Algorithm SHA256
```

Both outputs remain **local-only**. Aggregate logs may be shared after secret/provenance screening; never publish the input manifest or any local raw records/patterns. A passing run is a fresh alternative P40 audit, **not an execution of historical P33/P37 nor activation approval**. Record this distinction in issue #275.

## Versioned authorization and fallback boundary (nonexecuting)

`p40-profile-authorization.mjs` verifies the **syntax and Ed25519 signature** of a proposed, exact-repository-SHA, exact-project, time-limited (max 1h), per-profile Standard/Deep-only canary grant (max 5%). It checks an explicit externally supplied signer-key SHA256 against the DER public key and rejects unsigned, changed, wrong-project, wrong-SHA, Quick-inclusive and stale grants.

**This is not an owner signature service or a release authority.** Its output hardcodes `trust_anchor_independently_attested=false`, `grant_nonce_consumed=false`, `rollback_rehearsed=false`, `activation_authorized=false`, `repository_default_graph_enabled=false`, even for a cryptographically valid synthetic grant. A key fingerprint furnished by the same caller as the public key is not independent trust. A future independently reviewed trusted-key store, single-use nonce consumer, owner authorization and post-activation monitor are mandatory before any release actuator may exist.

`planP40FailClosedRollback` provides an explicit, allowlisted decision for manual revoke, expired/missing evidence, timeout/HTTP/source-stale/parity/quality/latency/monitor failure and rollback drills. Every result selects `legacy-control`, disables further Standard/Deep Graph transport and leaves Quick unchanged. It performs **no** state change, file write or runtime rollback; therefore a **real rollback rehearsal remains open** in #275.

No production router references either P40 component. The signed-grant test is a **synthetic verification test**, not evidence of actual owner signature or activation.
