# P61: protected Data API observation (default-off)

**Status: code-only preparation, NO-GO for production Standard/Deep routing.**

P61 is a **single bounded, read-only privileged P30 HTTP observation** intended
for an independently governed operator-run 24-hour soak. It makes no scheduler,
database, release approval, or Graph runtime modifications.

## Scope and fail-closed behavior

- CLI: reference-graph/cli/p61-observe-protected-transport.mjs
- Verifier: reference-graph/p61-protected-soak.mjs
- Requires a fresh P40 source-vs-projection witness JSON and a previously
  **independently archived exact SHA256** of its original bytes. The witness
  must still be valid both before and after the HTTP observation.
- Requires a valid **sb_secret_** credential ONLY in the trusted server
  environment variable P40_SUPABASE_SECRET_KEY; never accept it as a CLI
  argument. Use the exact protected P30 view, bounded GET-only fetch, strict
  P30 candidate count, sorted identity/digest, date, and refresh checks.
- Sanitized stdout only: time, candidate count, number of GETs, bounded
  duration and non-authorizing safety flags. Never print candidates, response
  body, key, asset IDs, request URL, or operator local paths.
- Always returns false for independent source attestation, complete
  24-hour soak, 48-case live parity attestation, release/activation and
  production rollback. A single successful read never upgrades those gates.

## Trusted-host operator steps

1. On a separately authenticated and read-only DB connection, run the
   unchanged file reference-graph/ops/p40-source-projection-witness.sql.
   Save ONLY the resulting p40_witness JSON object as a private local file,
   with a separate authenticated archive of its exact SHA256 bytes, SQL
   identity, trusted host identity, project and observation UTC time.
   No P31 refresh RPC.
2. On the authorized server, obtain the restricted sb_secret_ key from the
   locally approved secret manager, injected into process environment as
   P40_SUPABASE_SECRET_KEY. Never provide it in chat, GitHub, Firecrawl, logs,
   environment dumps, CLI arguments or result artifacts.
3. Run ONE observation within the witness's 15-minute life window, writing
   only its sanitized JSON stdout to a newly created private output file.

PowerShell 7 template (the witness hash is a placeholder, not evidence):

~~~powershell
$witness = 'C:\audit\reference-graph\p40-witness.json'
$witnessHash = '<independently-archived-64-character-lowercase-sha256>'
$output = 'C:\audit\reference-graph\p61-observation.json'

# Inject P40_SUPABASE_SECRET_KEY via your trusted local secret manager first.
node .\reference-graph\cli\p61-observe-protected-transport.mjs --witness-file $witness --witness-sha256 $witnessHash > $output
if ($LASTEXITCODE -ne 0) { throw 'P61 protected observation BLOCKED' }
Get-FileHash $output -Algorithm SHA256
~~~

   P61 itself starts no recurrent job or Windows/Supabase scheduler.
5. For genuine 48-case live approval, separately pin fresh P27 and P34
   Legacy baselines from P42 and the independent P40 witness BEFORE the
