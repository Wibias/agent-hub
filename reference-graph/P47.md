# P47: durable laboratory revocation and fail-closed coordinator restart

**Status: default-off, isolated lab-only, activation NO-GO.** P46 has an in-memory worker latch. P47 adds a persistent OFF-intent and signed revocation record for a single lab coordinator, so the test can reproduce restart and mid-write failure behavior.

`createP47DurableLabRevocation` accepts only an explicit `isolated-shadow-rehearsal`, Standard+Deep, `default_off:true`, `production_route_wiring:false`. Its caller must supply the already reviewed P46 public key, pinned key fingerprint, SHA and lab identity. It **never** creates signing keys, issues activation grants, reads Supabase or modifies P11.

The only `seedLabPermit` entrypoint is for an **empty test directory** with a separately supplied and valid signed short-lived P46 lease. No rearming after an OFF marker exists. `revokeWithSignedState` checks a valid signed revocation with a strictly larger sequence and first writes/fsyncs a permanent OFF-intent, then writes/fsyncs the signed revocation. If the process stops between those writes, `readSignedState` rejects the incomplete state, so it will never serve an old permit. It also rejects expired, forged or corrupt records and unreadable/untrusted paths.

Separate Node processes can read the state through a **loopback-only test HTTP server** and the existing P46 client. Restart of the server must re-read the persisted state, not use a stale memory copy. No networked coordinator is provisioned outside the isolated tests.

**Boundaries:** A local filesystem is not a production-grade cross-host durable store; signers are generated by tests, not independently attested. Directory fsync may behave differently by platform. A file may be deleted by a privileged host operator. Atomic read/GET/revocation fencing is not established by this interface. Expired signed revocations yield a blocked response rather than an extension of validity. No real production canary/rollback rehearsal, no release authority, no P11 or query import, no DB/cron/task update.

Before production: durable independently controlled backend, authenticated trust store, nonce/sequence ledger and signed owner release workflow, true distributed fencing, version-scoped kill-switch/rollback, latency/error quality budgets and separately authorized activation. Record the gap in issue #275.
