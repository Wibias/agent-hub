# P70: actual Standard/Deep Graph runtime behind a separate production release

**Decision: NOT APPROVED. Graph remains OFF.** This is a deployment-ready *integration code path* only; no permission or production credentials are included.

## The actual entry point

The already installed P69 local Windows binding routes `knowledge/design-references/scripts/query-runtime.mjs` -> `query-host-runtime.mjs` for Standard/Deep. P70 now adds a **single** branch to that real child:

1. If no trusted production release is independently enrolled, use **exactly the previous P69 signed-OFF probe and authentic P11 Legacy output**. There is no change to Quick, to P17's activation projection, or to the public JSON and usage semantics.
2. If all three *source-pinned* trust anchors are enrolled and the separate production manifest exists, verify two distinct Ed25519 signatures from the owner and independent reviewer over **one exact release payload**. Check P62's full versioned release-review record, exact project, checkout SHA, host, Standard/Deep scope, 1-5% Canary percentage, at most 1-hour UTC window, read-only source witness SHA-256 and the digest of the **entire discoverable installed ESM dependency graph** and the catalog JSONL inputs.
3. Only after validation does the real child call `runP70ApprovedProfile()`, which composes the existing P68 host wrapper and the **actual P67 profile Graph candidate runtime**. It uses a separately approved **production** coordinator and trusted signing key; the existing local P68 lab coordinator is explicitly excluded. P67 fetches protected P30 candidates, builds the independent P66 Graph public output, compares complete public JSON to authentic P11 and checks the signed, fresh shared state again before returning Graph.
4. If the coordinator is OFF, P67 returns Legacy. Missing pin, invalid grant, runtime file changes, stale evidence, deleted credentials, unavailable coordinator or Graph mismatch all fail closed. An unexpected P67 failure **after P11 has recorded usage** returns the memoized authentic Legacy result, preventing a second usage write.

## Exact release payload

One UTF-8 `payload_json` is signed **separately** with an externally custodied, trusted owner Ed25519 key and a **different**, independently verified reviewer key:

```json
{
  "payload_json": "<exact JSON bytes of release payload>",
  "owner_signature_base64": "<detached Ed25519>",
  "reviewer_signature_base64": "<different detached Ed25519>"
}
```

Payload fields (all required): `schema_version='reference-graph.p70-production-release.v1'`, `repository_sha`, `project_ref='vrznfnxzlxaavpqbzbzd'`, `operator_host_id`, `profiles`, `canary_percent`, `not_before`, `expires_at`, `runtime_artifact_sha256`, `witness_sha256`, and `release_review` (full P62 review record for the same SHA/host/profiles/window). The record carries the seven evidence digests, independently reviewed owner decision, operator identity, required rollback triggers and revocation ledger.

The runtime digest now starts from the **six entry modules**: `query-runtime.mjs`, `query-host-runtime.mjs`, the original `query.mjs`, `p69-installed-off-host.mjs`, `p70-production-release-gate.mjs` and `p70-production-host-config.mjs`. It follows all literal transitive relative ESM imports, **including the delayed P68 -> P67 -> P66/P30 Graph path**. Computed dynamic imports, missing files, symlinks, path traversal and unreadable catalog directories fail closed. It additionally hashes `taxonomy.json` and every `.jsonl` input consumed under `knowledge/design-references/data` and `patterns`, including Git-ignored additions. The sorted digest input is each relative path + NUL + SHA-256(file bytes), joined by newline and SHA-256 of the whole UTF-8 string. The exact digest must be included in both owner/reviewer signatures. **Until the entire Graph dependency set is installed, the non-authorizing Windows P70 OFF path remains the only allowed mode.**

## Production configuration

The trusted host reads `AGENTHUB_P70_DEPLOYMENT_MANIFEST` only **after** all three source-enrolled trust pins are valid. Its JSON schema `reference-graph.p70-trusted-host-config.v1` contains exactly: `schema_version`, `repository_sha`, `operator_host_id`, `release_envelope_path`, `owner_public_key_path`, `reviewer_public_key_path`, `coordinator_public_key_path`, `state_endpoint`, `state_read_token_path`, `service_key_path`, and `witness_json_path`. Paths are absolute, regular non-symlink files. Private credentials are **never** logged or inserted into browser/CLI arguments. The independent production coordinator must be an HTTPS server other than the installed `127.0.0.1`/localhost P68 lab server, with its own distinct approved Ed25519 state-signing key. The host must provision its TLS trust chain and stable authenticated operator host identity.

**Current code deliberately ships all three enrolled production SHA-256 SPKI trust pins as `null`.** It cannot accept an arbitrary key, a local owner-generated key or an environment flag as release authorization. A later separate reviewed source change to the fixed pins, after independently verified signing custody/evidence, is mandatory. Never auto-enroll from a test or a PR merge.

P70 now enforces the owner-approved maximum Canary percentage at the protected P67 boundary. A coordinator-signed higher percentage is rejected and latched OFF before any protected P30 GET. The sample percentage is an expectation, not a hard deterministic traffic cap over small samples; a separately approved traffic-metering and abort rule remains necessary.

## Remaining approval facts

P62 validates release-record **structure only**. Even two valid detached signatures do not by themselves establish the independent authenticity of frozen P26 source evidence, new same-snapshot P31/P7 provenance, historical P33/P37 verification, security budget, multi-host rollback or monitoring. Those evidence requirements remain the seven **open** checkboxes in [Issue #275](https://github.com/Wibias/agent-hub/issues/275) and must be verified externally. **No production permission, live service credential or complete evidence packet exists in this PR.**

This is an intentional code-merge versus production-activation separation. The new path is ready for review, but the source-enrolled pins, real coordinator/host registration and exact evidence/approval gate remain **NO-GO**. Do not merge the stacked Drafts or activate Graph merely because this PR's unit tests pass.
