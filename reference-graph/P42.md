# P42: local Legacy evidence freezer (preparation only, no release authority)

This tool removes manual P27/P34/records/patterns/template file assembly from the P40 operator flow.

**Executable:** `reference-graph/cli/p42-freeze-legacy-evidence.mjs`. It does not need a Supabase credential, does not access the network, and never changes routing, P11, P35, the database, the Windows Task Scheduler or user-usage logs.

## Input identity and guard

The operator checkout must be a **clean Git descendant** of merged #274 commit `83a3794cc54d2f2d129b83e8e672e18b35f11cff`. Before writing, the command checks Git's original blobs: the complete `knowledge/design-references` catalog and all Legacy-control selector and baseline files must be byte-identical to that merge. Any drift, dirty checkout, missing Git history or unknown legacy source **fails closed**. The tool writes only a NEW absolute output directory, never overwrites existing evidence. On Windows use a private folder under `%LOCALAPPDATA%` with appropriate NTFS permissions, **outside the repository**.

Example (PowerShell 7, from a separate clean checkout of Draft #276, not the pinned Windows P38 monitor checkout):

```powershell
$utcDate = [DateTime]::UtcNow.ToString('yyyy-MM-dd')
$out = Join-Path $env:LOCALAPPDATA ("agent-hub\reference-graph\audit-" + $utcDate + "-01")
node .\reference-graph\cli\p42-freeze-legacy-evidence.mjs --date $utcDate --out-dir $out
if ($LASTEXITCODE -ne 0) { throw "P42 freeze blocked" }
```

Outputs (private local-only): `p27-baseline.json`, `p34-public-baseline.json`, `records.json`, `patterns.json`, `templates.json`, `p42-local-index.json` and `p40-manifest-DRAFT.json`.

The index lists the exact committed checkout SHA, unchanged Legacy baseline SHA, file paths, byte sizes and SHA256 for all five inputs. The draft manifest deliberately contains `sourceWitness.sha256: "UNATTESTED"` so it is **rejected by the P40 CLI**. It must be updated only after an independently authenticated read-only P40 witness is acquired and pinned. Generating these hashes locally is **not an independent human or external-source attestation** and does **not** satisfy #275 by itself.

## Subsequent staged live procedure (separate explicit operator actions)

1. Independently authenticate and archive current P40 witness from `reference-graph/ops/p40-source-projection-witness.sql`; record the actual SQL source, project, trusted operator identity, query/refresh UTC timestamps and SHA256 of the exact saved JSON bytes. Do not call any P31 refresh function. Use a fresh witness for each two-stage window; max 15 minutes.
2. Populate `p40-manifest-DRAFT.json` with the witness filename and independently archived exact SHA256. Do not change the five frozen input file pins. The manifest is now eligible for `p40-operator-readonly-audit.mjs --stage record` on a trusted machine using the locally held `P40_SUPABASE_SECRET_KEY`; save its compact JSON and independently archive its SHA256.
3. Once a separate trusted process has pinned the **exact stage-one output bytes**, set `approved_record_report_sha256` to that digest in the same local manifest. Run `--stage full` **before the witness expires and before a P38 refresh changes the candidate snapshot**. Confirm 48/48 record, pattern and full-public-output equality and archive the aggregate report. Each failure or changed refresh requires a new witness and a new attempt.
4. Run the separate P41 Standard and Deep operator shadow requests, again with a fresh witness and the same published snapshot. They retain Legacy authority; no production Graph traffic is enabled.

**Unresolved for activation:** independently accepted new evidence method, actual external/human validation of archived control and report pins, authorization policy/trust anchor, real default-off canary actuator, quantitative latency/error/quality budgets and a real rollback rehearsal. Only #275 can track those. No P42 success itself means GO for Graph activation.
