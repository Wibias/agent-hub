# P37: single-snapshot P33/P34 Standard/Deep audit (review-only)

**NO-GO for deployment, database migration, Standard/Deep routing, repository-default promotion or automatic merge.**

P37 is stacked on unmerged P36 PR #236 (the full-content binding), itself stacked on P30 pagination fix #235. No existing PR, P11 router, Quick/P25, Windows collector, production database or scheduler is modified.

## Gap closed

P33 v2 fetches and validates a complete P30 candidate population but returns only aggregate evidence. P34 v2 needs the same in-memory candidate DTOs to compute full pattern/public-output parity. Without an orchestrator, an operator must either repeat the network read or carry raw candidate data through other systems.

The new library at reference-graph/p37-single-snapshot-public-audit.mjs exports auditP37SingleSnapshotPublicParity(input). It transiently captures **only the JSON pages already consumed by P33's validated P30 GET**, then passes the validated DTOs to P34 in memory. It neither returns nor stores the raw pages, records, patterns or credentials. It makes no second HTTP retrieval for P34.

A single **logical snapshot retrieval** may require multiple sequential GET requests when the candidate count exceeds the server's row cap. The aggregate http_request_count reports the count of page requests, not the number of separate audits.

## Strict operator inputs

The caller supplies:

- Exact dedicated AgentHub Reference Graph HTTPS project URL and publishable-only key. P33 rejects all other project identities and P30 enforces read-only GET.
- Explicit UTC asOf, bounded timeout, independently pinned P31 source-receipt JSON/hash and 24-template P27 Standard/Deep baseline JSON/hash.
- Independently frozen local record and pattern catalogs, and all 48 P11 legacy public-output hashes, each supplied as exact JSON and its SHA-256.
- A **separately approved, previously captured P33 v2 aggregate report SHA-256**, named expectedP33ReportSha256, required before any network call.

P37 verifies all local P34 byte pins before HTTP and uses P33's independent pin/receipt/target checks. After P33 completes, P37 compares the resulting redacted report bytes against the independently supplied P33 SHA. It **does not create this trusted pin from its own just-fetched P33 output**.

P37 strips P30-only snapshot fields, passes validated DTOs to P34, and P34 verifies its full canonical candidate-content SHA-256 against the P33 v2 aggregate before evaluating the 48-case pattern/public-output baseline.

The redacted P37 receipt contains only P33 and P34 aggregates, page-request count, input-report pin match, and **permanently false** release fields. It never prints private candidates, search text, tokens, HTTP bodies or raw catalog data.

## CI limitations

CI uses the real local catalog, mock P30 HTTP, synthetic P31 receipt and locally generated hashes. Its six new tests verify 48/48 single-read composition, refusal of missing/incorrect P33 pins, offline byte-pin rejection before HTTP, identity-preserving metadata drift rejection, HTTP failure and source isolation. Test-generated pins have no independent provenance and therefore do not establish live parity.

Even a perfect P37 report always sets live_graph_parity_verified, deployment_authorized, activation_authorized, repository_default_graph_enabled and eligible_for_activation to **false**.
