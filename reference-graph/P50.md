# P50: separately attested P49 CI evidence (production NO-GO)

P49 already proves an isolated mTLS Docker rehearsal on one GitHub CI host. P50 creates a strict, **public, secret-free** JSON evidence subject from that exact P49 machine report, then uses a **separate GitHub Actions job** to sign its SHA256 digest with GitHub's OIDC/Sigstore artifact-attestation facility.

- `reference-graph/cli/p50-create-ci-evidence.mjs` validates the exact P49 report schema, including all positive and negative flags, expected container count, TLS version, and the immutably pinned Node image digest. Missing fields, new unreviewed fields, forged activation bits and inconsistent checkout IDs are rejected.
- The manifest records actual checkout SHA and PR head SHA separately. PR CI can check out a synthetic merge commit, so these two hashes must not be confused.
- The P49 Docker job retains read-only repository permissions. It uploads only the validated public report. The separate privileged GitHub attestation job downloads the artifact, **does not check out the PR or execute PR-supplied code**, and attests the exact artifact digest. Fork PRs do not receive that privileged job.
- A signed GitHub artifact attestation proves the subject digest and GitHub workflow identity, not that the P49 test assertions are inherently correct, not independent Supabase source acquisition, and not human/owner release approval.
- Verify the downloaded artifact with `gh attestation verify p50-ci-evidence.json -R Wibias/agent-hub`. A verifier must also inspect the schema, checkout/head SHA and all explicit false release flags. The attestation itself is not asserted by the unsigned JSON file.

All independent-source, independent-review, productive-rollback and activation assertions remain false. P35-protected paths and the original governance workflow remain unchanged. The one-time #274 owner exception does not authorize #276.
