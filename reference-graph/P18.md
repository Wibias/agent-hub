# Reference Graph P18 — Production Activation Ceremony

P18 is the deliberate production cutover ceremony for the Quick Reference Graph runtime. It keeps the Ed25519 signing key outside AgentHub, verifies a short-lived externally signed grant, performs a read-only production preflight, then delegates the actual one-shot activation to the already-governed P15/P16/P17 path.

## Hard boundary

P18 production code does **not** generate, import, decrypt, or sign with a private key. The authority private key must remain outside the repository and outside `~/.agents` / `%USERPROFILE%\.agents`.

The recommended Windows custody directory is:

```powershell
$AuthorityDir = Join-Path $HOME ".agent-hub-authority"
New-Item -ItemType Directory -Force $AuthorityDir | Out-Null
```

Do not put this directory under the AgentHub checkout. Do not add it to Git. Do not pass the private-key passphrase on the command line or through an environment variable.

## 1. Generate the external Ed25519 authority

Use OpenSSL 3 or later. The private PKCS#8 file is encrypted and OpenSSL prompts interactively for its passphrase:

```powershell
openssl genpkey -algorithm ED25519 -aes-256-cbc -out "$AuthorityDir\authority-private.pem"
```

Export only the public key as SPKI DER:

```powershell
openssl pkey -in "$AuthorityDir\authority-private.pem" -pubout -outform DER -out "$AuthorityDir\authority-public.der"
```

The private key remains in `$AuthorityDir`. AgentHub receives only `authority-public.der`.

## 2. Build and inspect the public authority descriptor

From the AgentHub runtime root (`%USERPROFILE%\.agents`, or the active `AGENTS_HOME`):

```powershell
node reference-graph/cli/p18-production-activation.mjs `
  --authority-descriptor `
  "$AuthorityDir\authority-public.der" `
  "agent-hub-production-authority" `
  "agent-hub-production-2026-10" `
  "$AuthorityDir\authority.json"
```

The command prints the canonical authority SHA-256. Inspect the exported public key independently if desired:

```powershell
openssl pkey -pubin -inform DER -in "$AuthorityDir\authority-public.der" -text -noout
```

Recompute the descriptor hash explicitly:

```powershell
node reference-graph/cli/p18-production-activation.mjs --authority-hash "$AuthorityDir\authority.json"
```

After inspecting the authority descriptor and public key, manually place the exact approved lowercase 64-character SHA-256 into:

```text
%USERPROFILE%\.agent-hub-authority\authority-approved.sha256
```

The approval file must contain only that digest and a trailing newline at most. P18 will reject any mismatch. This is the external trust anchor; the ceremony never self-approves a different descriptor.

## 3. Load production Supabase credentials into the current operator process

The target is fixed to:

```text
https://vrznfnxzlxaavpqbzbzd.supabase.co
```

Set the URL and current publishable key in the current PowerShell process. Prefer a modern Supabase secret key for the one service-only P16 consume RPC:

```powershell
$env:SUPABASE_URL = "https://vrznfnxzlxaavpqbzbzd.supabase.co"
$env:SUPABASE_PUBLISHABLE_KEY = "<current publishable key>"
$env:SUPABASE_SECRET_KEY = "<current sb_secret_... key>"
```

A legacy `SUPABASE_SERVICE_ROLE_KEY` remains supported as a fallback when no `SUPABASE_SECRET_KEY` is set:

```powershell
Remove-Item Env:SUPABASE_SECRET_KEY -ErrorAction SilentlyContinue
$env:SUPABASE_SERVICE_ROLE_KEY = "<legacy service-role JWT>"
```

Do not pass either elevated key as a CLI argument and do not write it into any ceremony file. Modern `sb_secret_...` credentials are sent only through the Supabase `apikey` header; they are not used as bearer tokens.

## 4. Prepare a fresh ten-minute grant

This creates a fresh random 256-bit nonce, an unsigned JSON payload, and the exact canonical UTF-8 bytes that must be signed. The grant expires ten minutes after preparation:

```powershell
node reference-graph/cli/p18-production-activation.mjs `
  --prepare-grant `
  "$AuthorityDir\authority.json" `
  "$AuthorityDir\authority-approved.sha256" `
  "$AuthorityDir\grant.payload.json" `
  "$AuthorityDir\grant.canonical.json"
```

The printed value is the SHA-256 of the exact canonical payload.

## 5. Sign the exact canonical bytes externally

OpenSSL prompts for the encrypted private-key passphrase. Ed25519 uses raw signing; no digest is supplied:

```powershell
openssl pkeyutl -sign -rawin `
  -inkey "$AuthorityDir\authority-private.pem" `
  -in "$AuthorityDir\grant.canonical.json" `
  -out "$AuthorityDir\grant.sig"
```

AgentHub never sees the private key or its passphrase.

## 6. Assemble and cryptographically verify the signed grant

```powershell
node reference-graph/cli/p18-production-activation.mjs `
  --assemble-grant `
  "$AuthorityDir\authority.json" `
  "$AuthorityDir\authority-approved.sha256" `
  "$AuthorityDir\grant.payload.json" `
  "$AuthorityDir\grant.sig" `
  "$AuthorityDir\grant.json"
```

The command refuses to write a usable grant unless the raw signature is exactly 64 bytes and verifies against the independently approved Ed25519 authority.

## 7. Run read-only production preflight

Run preflight before any one-shot nonce is consumed:

```powershell
node reference-graph/cli/p18-production-activation.mjs `
  --preflight `
  "$AuthorityDir\authority.json" `
  "$AuthorityDir\authority-approved.sha256" `
  "$AuthorityDir\grant.json"
```

Preflight verifies:

- the exact dedicated Supabase project URL;
- presence of the publishable runtime key;
- presence of a modern secret key or legacy service-role fallback;
- exact independent authority approval;
- the current signed grant and its expiry;
- the local P17 state is still `legacy-control` with Quick graph disabled.

Preflight is read-only. It does not instantiate the P16 consuming store and does not consume a nonce.

## 8. Execute the one-shot production activation

Only after preflight returns `preflight_ready: true`, run the exact confirmation token:

```powershell
node reference-graph/cli/p18-production-activation.mjs `
  --activate-production `
  "$AuthorityDir\authority.json" `
  "$AuthorityDir\authority-approved.sha256" `
  "$AuthorityDir\grant.json" `
  ACTIVATE-QUICK-REFERENCE-GRAPH
```

The production path is then:

1. P18 repeats the read-only preflight.
2. P15 re-verifies the signed grant.
3. P15 verifies production is still legacy.
4. P16 irreversibly consumes the nonce before local mutation.
5. P15 performs a fresh time verification.
6. P17 atomically projects graph mode for future design-reference query children.
7. The live probe requires **Quick → `reference-graph`** with exact record and pattern parity.
8. The same live probe requires **Standard → `legacy-control`** and **Deep → `legacy-control`**.
9. Any post-mutation failure invokes P17 rollback and a second probe must verify all profiles are restored to legacy before the result can say `rolled-back`.

A consumed grant is never retried. Generate and sign a new grant for any later attempt.

The CLI output is an allowlisted, secret-free receipt. It omits the raw grant, signature, nonce, consumption ID, activation change ID, credentials, and authority file paths.

## 9. Check current local runtime state

This mode needs no Supabase credentials:

```powershell
node reference-graph/cli/p18-production-activation.mjs --status
```

Before the real ceremony, expected production state remains:

```json
{
  "production_source": "legacy-control",
  "quick_graph_enabled": false,
  "repository_default_graph_enabled": false
}
```

## Credential cleanup

After the ceremony, clear elevated credentials from the current PowerShell process:

```powershell
Remove-Item Env:SUPABASE_SECRET_KEY -ErrorAction SilentlyContinue
Remove-Item Env:SUPABASE_SERVICE_ROLE_KEY -ErrorAction SilentlyContinue
```

The publishable key may remain available to the runtime as required by the Quick graph projection. The encrypted authority private key remains external in `.agent-hub-authority`; it is never copied into `.agents`.

## Current phase status

Repository implementation and CI alone do not activate production. Until the actual external authority is created, a real ten-minute grant is signed, and the exact activation command is run on the production Windows host:

- production remains `legacy-control`;
- no live P16 nonce is consumed by P18 CI;
- `activation_performed=false`;
- Quick remains legacy by default;
- Standard and Deep remain `legacy-control`.
