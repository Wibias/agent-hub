## Implemented

- Standalone module: reference-graph/p30-profile-transport.mjs. It is NOT imported by P11, production CLI defaults or collectors.
- Future projection name: reference_graph_profile_runtime_projection_p30_v1. P10's current Quick projection is unchanged. **This future projection has no deployed migration, and P30 does not claim that it exists on Supabase.**
- One-shot HTTPS GET with an explicit date filter, strict selected columns, stable asset order and publishable-key authentication. No privileged credential, RPC or write operations.
- Exactly the 16 P28 candidate fields plus projection version, snapshot date, and refresh timestamp. Rejects extra/missing fields, invalid strata, duplicate IDs, unordered assets and inconsistent snapshot bindings.
- An *independently supplied* UTC date, as-of instant, candidate count and canonical candidate legacy-ID-set SHA-256 are mandatory before the request. Any structural, time or fingerprint mismatch fails closed.
- Fixed, redacted error categories and a bounded timeout. Returned transport metadata contains only aggregate information and explicit false flags for parity, activation and repository-default Graph routing.

## Invocation contract

A future operator must independently pin the arguments to fetchP30ProfileCandidateSnapshot: supabaseUrl, publishableKey, expectedDate, asOf, expectedCandidateCount and expectedCandidateIdSetSha256. The pins must not be derived from the same untrusted response being validated. This is only an interface contract, not an authorized working production command.

The date is UTC and asOf must be an independently trusted UTC observation time. A caller-chosen historical asOf does not prove present-day freshness. Maximum permitted age is four hours; permitted future timestamp skew is one minute.
