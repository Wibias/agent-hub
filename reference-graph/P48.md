# P48: authenticated loopback-only P47 coordinator (NO-GO for production)

**Default-off, isolated lab-only.** P47 persists signed revocation state; P48 reads that state on each authenticated GET via a server bound strictly to `127.0.0.1`. There is no HTTP mutation route.

`startP48AuthenticatedLabCoordinator` requires a random base64url bearer token (at least 32 random bytes) supplied by the test operator, plus a P47 signed-state reader. Requests with missing, duplicate or wrong authorization headers fail. Non-GET methods, unknown paths and body-bearing GETs cannot access state. Errors produce generic status responses without leaking keys, paths or candidate data. Each successful request re-reads P47 to enforce durable revocations and reject incomplete journals. No permits are cached.

The coordinator holds **no private Ed25519 signing key** and cannot issue authorizations. P46 workers separately validate the signed envelope, dedicated project/commit/lab identity, lease expiry and sequence. The bearer token is a separate *read-only lab credential*, not the owner signing key.

Tests should use ephemeral Ed25519 keys and random bearer tokens. Exercise real independent Node worker processes, invalid bearer requests, credential rotation, coordinator restart, persisted revocation and partition failures. The test-only server is never started by production routing.

**Security boundary:** This is **HTTP over loopback, not TLS/mTLS**. Never proxy or expose its port to other hosts. A real multi-host service requires verified TLS/mTLS, authenticated independent signer trust, a durable backend with fenced lease/revocation transactions, protected nonce/sequence ledger, operational metrics and rollback rehearsal. Local host administrators can tamper with test files or environment. Successful P48 tests do not constitute production readiness.

P11, public query, historic P33/P35, Supabase and Windows monitoring are untouched. Activation remains NO-GO in issue #275.
