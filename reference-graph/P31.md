## Scope

The P31 proposal is an additive PostgreSQL migration:
`reference-graph/schema/014_reference_graph_profile_projection_p31.sql`.

It defines a separate versioned projection:
`public.reference_graph_profile_runtime_projection_p30_v1`.

P10 Quick schema, P11 default routing, P17/P19 authority, the production P25 Quick collector and the Windows collector are not modified. P31 adds no scheduled refresh, automatic activation, grants to the private graph source tables, or production connection code.

The proposed public projection contains the exact 16 P28 profile candidate fields plus `projection_version`, `snapshot_date`, `refreshed_at`. `primary_stratum` must be one of the four taxonomy values. The version has a fixed check constraint.

The historical 014 state had RLS enabled, a `SELECT`-only grant to `anon` and `authenticated`, and a UTC-current-snapshot policy. P39 migration 016 revokes that direct public table grant; public consumers use the safe view, while the full candidate read is service-only.

## Privileged refresh

The proposed function `public.reference_graph_refresh_profile_runtime_projection_p31()` is granted only to `service_role`. It returns only aggregate snapshot metadata and false flags for parity, activation and repository-default routing. No raw record IDs, free-text queries, privileged tokens, or source provenance are returned.

A refresh:
1. Pins one UTC snapshot date and timestamp.
2. Queries the existing P7 eligible candidate source and calculates its **source-side count and sorted legacy-ID-set SHA-256**.
3. Joins those *same* P7 asset IDs to `reference_graph.current_assets` for the stored `asset.metadata.primary_stratum`. Missing/invalid strata cause an error before replacement.
4. Replaces the versioned projection within a single PostgreSQL transaction.
5. Checks published count and sorted legacy-ID-set fingerprint against the source-side reference. Any mismatch or constraint violation aborts the transaction, preserving the prior committed snapshot.
6. Returns an operator-only aggregate receipt with `expected_candidate_count` and `expected_candidate_id_set_sha256`.

The P7 source preserves current eligibility semantics. The P31 function is **not** a new independent review/certification of source quality. The SQL-derived receipt is a trusted-operator transport precondition, not independent evidence that Supabase live records match the local P27 catalog. An operator must independently bind the receipt to the intended project, date, execution and response before using it as a P30 expected-hash pin.

## Verification

`tests/reference-graph/p31-profile-projection.test.mjs` tests the structural contract and routing isolation.

`tests/reference-graph/p31-profile-projection-smoke.sql` runs only against the disposable PostgreSQL CI service, after P7/P10 fixture setup. It checks:
- RLS grants, UTC visibility, service-role-only execution and forbidden anonymous/authenticated writes;
- missing/invalid `primary_stratum` fails closed;
- P7 source membership and published membership hash equality;
- expired snapshot rows are invisible to publishable roles;
- both early-validation and mid-insert failures preserve the last committed snapshot;
- existing P10 Quick population remains unchanged.

The P30 read client now normalizes a PostgreSQL/PostgREST UTC `timestamptz` response (including `+00:00` and microseconds) to its canonical millisecond UTC form. It still rejects non-UTC offsets or malformed time values. Tests use mocked HTTP; a real authenticated PostgREST roundtrip remains unverified.

## Non-goals and next gates

- **No live migration** is executed as part of P31. A migration file passing disposable CI is not deployed schema.
- No live Supabase Data API exposure/RLS inspection, publication audit, project-specific grants, real refresh receipt, live 48-case P29 parity, full pattern/output parity, relevance evidence or latency/error budget is established.
- A live deployment would require a distinct, explicit production change approval after independent PR review, detailed threat review, migration/rollback plan, verified target project and operational checks. Do not use an elevated key in a user-facing client.
- P30 remains disconnected from all default routing. Standard and Deep remain legacy-only under P11. The P25 Quick path must stay unchanged.
