# P28: profile-aware candidate metadata contract (offline, default-off)

**Scope:** an offline structural audit supporting future Standard/Deep Graph
retrieval research. This is **not** a Graph transport deployment, repository
default promotion, or a certified Standard/Deep parity policy.

## Observed blocker

The existing P10 production candidate projection
`reference_graph_quick_runtime_projection_p10` has no
`primary_stratum` column. The P10 publishable read client also does not
select such a field. The source capture already stores
`asset.metadata.primary_stratum`, but P8's public Quick candidate object
does not expose it.

Legacy Deep selection depends on per-stratum minima and maxima from
`knowledge/design-references/taxonomy.json`, so the current P10 candidate
shape cannot reproduce Deep's coverage quotas independently.

## P28 offline experiment

Two paths use the same **local** reviewed, fresh and accessible source
records at an explicit UTC reference date:

1. `current_p10_equivalent`: the existing P8 offline Quick candidate
   adapter, whose **structure** mirrors the P10 candidate metadata. It lacks
   `primary_stratum` and is expected to fail the proposed P28 contract.
2. `proposed_offline`: the same P8 candidate identities with
   `primary_stratum` sourced from their corresponding reviewed legacy
   record, validated against the exact taxonomy strata.

The strict P28 audit checks the allowed candidate keys, identities,
duplicate IDs, the stratum vocabulary, and basic field types. It reports
only counts, a canonical candidate-ID-set SHA-256 and bounded blocker
categories. The audit never serializes individual candidate IDs,
searchable text, full records, local paths, credentials or private source
evidence in its stdout report.

`metadata_contract_complete=true` on the proposed **offline** form
means only the selected metadata schema is complete. It does not mean that
the real Supabase projection has been migrated, that its RLS or freshness
is correct, that graph selection matches Standard/Deep legacy, or that
retrieval quality is improved.

## Required separate follow-up

- Design and independently review an additive future projection including
  `primary_stratum`, with no expansion of publishable privileges and a
  versioned target distinct from the current P10 Quick path.
- Prove full end-to-end transport snapshot bindings, RLS read permissions,
  freshness and source provenance on the expanded projection.
- Implement a **distinct** Standard/Deep selection policy with quotas,
  negative-case coverage and independent public result/pattern parity tests
  against P27's baseline. Never simply call legacy `selectRecords` on
  hydrated Graph records and count that as independent graph parity.
- Define latency/availability/error budgets and a bounded rollback for
  whichever exact profile scope is eventually proposed.
- Implement a new default-off, independently approved control and post-change
  health receipt. Existing P19 explicitly requires repository-default off.
- Demand a separate production authorization; do not use P25's Quick
  evidence to assert Standard/Deep readiness.

P28 is stacked on P27 (PR #226). Neither PR requires an active Graph
instance or changes the approved P25 collector.
