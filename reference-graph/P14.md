# P14 Authority Enrollment and Grant Ceremony

P14 authority enrollment adds the next fail-closed boundary after P13. It binds production public-authority enrollment and externally signed grant verification to the final P13 evidence head `bbd29fbe596801fdb7594f45045cb41e9c9b1a5b`, exact P13 evidence SHA-256 `06fdedcca135ce0e7e819b1ddc61e861a6c37ea01f5fbee006fdfcd2e709843e`, and canonical P13 request hash `ed31630f9bda1362f42e747a6366d8504d17638b8ba458228db6fec5a2074ce7`.

P14 does not activate Reference Graph routing. It does not generate, import, parse, store, or sign with a production private key. Production private-key custody is external to this repository, CI, and operator. The repository handles only the public Ed25519 authority descriptor, an independent approval hash, unsigned canonical grant payloads, returned detached signatures, and verification receipts.

## Trust model

A public key is not trusted merely because it exists in Git. Enrollment requires all of the following:

- the exact P13 evidence bytes and request remain frozen;
- the authority descriptor uses the exact P13 Ed25519 authority schema;
- the SPKI key is actually Ed25519;
- the separately supplied `approved_authority_sha256` is a lowercase SHA-256 digest;
- `approved_authority_sha256` exactly equals the canonical authority descriptor hash;
- the enrollment manifest records `environment: production`;
- private-key custody is `external`;
- `private_key_present` is false.

The approval hash is an external ceremony input. P14 never derives trust from the authority descriptor alone.

## External signing ceremony

P14 emits the exact unsigned P13 grant payload. The payload is bound to:

- the final P13 request hash;
- the frozen P12 evidence head and binding inherited through P13;
- the dedicated Reference Graph target;
- `profile: quick`;
- `REFERENCE_GRAPH_QUICK_RUNTIME=graph`;
- the enrolled authority and key identifiers;
- canonical UTC ISO timestamps;
- a 32-byte lowercase-hex nonce;
- a lifetime greater than zero and no more than 15 minutes;
- `signature_algorithm: Ed25519`.

The operator does not sign this payload. The canonical payload bytes must be signed by the externally held Ed25519 private key. The returned detached signature is assembled into the P13 grant envelope and verified by the hardened P13 verifier.

A valid signature from an authority whose approval hash is missing or mismatched is still unauthorized.

## Operator

The read-only/output-only operator is:

```text
node reference-graph/cli/p14-authority-enrollment-grant.mjs --plan
node reference-graph/cli/p14-authority-enrollment-grant.mjs --verify-repository
node reference-graph/cli/p14-authority-enrollment-grant.mjs --enrollment-manifest <authority.json> <approved-authority-sha256>
node reference-graph/cli/p14-authority-enrollment-grant.mjs --emit-grant-payload <authority.json> <approved-authority-sha256> <issued-at> <not-before> <expires-at> <nonce>
node reference-graph/cli/p14-authority-enrollment-grant.mjs --verify-signed-grant <authority.json> <approved-authority-sha256> <grant.json> <now-iso>
node reference-graph/cli/p14-authority-enrollment-grant.mjs --finalize-repository <snapshot.json>
node reference-graph/cli/p14-authority-enrollment-grant.mjs --finalize-ceremony <snapshot.json> <authority.json> <approved-authority-sha256> <grant.json> <now-iso>
```

The operator may read repository files and caller-supplied JSON and may emit JSON to stdout. It does not write repository files, generate keys, sign payloads, set environment variables, deploy, call Supabase, refresh projections, execute write RPCs, or activate routing.

## Ceremony-ready state

The repository can finish P14 infrastructure without inventing a production signer. Until a real external production authority and signature are supplied, durable P14 evidence records:

```text
ceremony_ready: true
authority_state: awaiting-external-enrollment
grant_state: not-issued
grant_verified: false
activation_authorized: false
activation_performed: false
repository_default_graph_enabled: false
production_source: legacy-control
external_blocker: production-ed25519-authority-not-provided
```

This is a successful infrastructure state. It is not a production authority enrollment and not a grant issuance.

Ephemeral test keys prove the ceremony code path only. They must never become durable production authority artifacts.

## Authorized-not-activated state

If a real externally held production authority is enrolled and its exact signed grant verifies, P14 may record the authorized-not-activated state:

```text
authority_state: enrolled
grant_state: issued
grant_verified: true
activation_authorized: true
activation_performed: false
repository_default_graph_enabled: false
production_source: legacy-control
```

Authorization is not activation. P14 never changes `REFERENCE_GRAPH_QUICK_RUNTIME`, deployment configuration, routing, Supabase state, or database schema.

## Hard stop

P14 stops at authority enrollment and grant authorization evidence.

Even after a valid production grant:

- `activation_performed: false` remains mandatory;
- repository default remains graph-off;
- `production_source: legacy-control` remains mandatory;
- standard and deep remain legacy-only;
- no migration `010+` is introduced;
- no Supabase mutation occurs.

A later explicit activation phase must separately consume a still-valid authorized grant and perform any production routing change under its own rollback and evidence contract.
