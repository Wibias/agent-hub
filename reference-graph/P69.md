# P69: bind the actual AgentHub Standard/Deep CLI to the installed P68 OFF host

**Scope: real CLI integration, local signed-OFF proof only. No Graph activation.**

AgentHub's documented real entry is `knowledge/design-references/scripts/query-runtime.mjs`; it previously started `query.mjs` for every profile. P69 changes this **entrypoint** to select `query-host-runtime.mjs` for Standard/Deep only when the private Windows P69 binding file exists. Quick still uses the unchanged P17 `query.mjs` path, state projection and P10 transport.

The already installed P68 coordinator is pinned to `477282f0eba1a848d06d928c70890fb0add784b8`. The Windows installer created a local **NON-AUTHORIZING** owner verification key, discarded its private half, started a loopback TLS server and verified its P67 `OFF` response. **This is not an approved production signer or a production Canary.** P69 makes that fact an explicit runtime security property rather than silently accepting lab permits.

## What P69 does, exactly

- An explicit binding config, placed by the host operator under `%LOCALAPPDATA%\AgentsHub\ReferenceGraphHost-P68\p69-host-binding.json`, names only `https://127.0.0.1:<port>/state`, exact P68 repository SHA, TLS certificate path, Ed25519 verification key path and SHA256 SPKI pin, and the protected local bearer-token file path. No token or key bytes are embedded in the binding JSON or repository.
- Standard/Deep query-runtime dispatches to the P69 child without changing the current command-line flags or stdout shape. P69 validates exact project, version, state schema, 128-bit challenge, 3-second HTTPS response, TLS trust, Ed25519 signature, signer pin, freshness and **signed OFF**. No Graph candidate API request or service-role credential exists in P69.
- **Any** missing/invalid/unreachable P68 state, unauthorized TLS peer, bad signature, or *even a valid P68 lab Canary grant* is **LEGACY**. P69 calls the unchanged P11 control exactly once with `graphMode:'legacy'`, preserving ordinary single-shot local usage recording, JSON fields, exit codes and Quick behavior.
- If `AGENTHUB_P69_DIAGNOSTICS=1`, stderr prints only one sanitized status: `P69_REAL_CLI_P68_SIGNED_OFF_CONNECTED` or `P69_REAL_CLI_P68_UNAVAILABLE_OR_NOT_OFF_LEGACY`. Stdout stays byte-identical to the existing Legacy public query.
- The binding does not authorize or expose Graph. A signed external production owner grant cannot be inferred from the P68 test token, test signer, source hash or disabled test permit.

## Deployment boundary

P69 code is a **stacked Draft** after #281 -> #282 -> #283 -> #284. No source file was installed into the user's real `~/.agents` checkout by opening the PR. The Windows operator installation must verify the existing `query-runtime.mjs` has the reviewed baseline Git blob hash, create a backup, copy exactly the three P69 runtime files, create a private local binding pointing to the live P68 port, then execute a real Standard/Deep query through **the existing AgentHub command** with a signed OFF diagnostic. Quick and Legacy stdout must remain unchanged.

A manual bind/unbind package is separate from this PR and should refuse modified/unexpected installations rather than clobber local changes. The P68 listener is bound to an ephemeral port; after a coordinator restart the operator must refresh the binding or the runtime will safely use Legacy.

## What is not done

- No autonomous access to the owner's Windows host from GitHub/ChatGPT; an operator must run the local bind command.
- No deployed production Standard/Deep service is created: existing AgentHub is a **local CLI**.
- **No production Canary or production release approval.** The installed P68 service remains OFF only, no service-role key is configured, and the separately required owner signer is not enrolled.
- No Windows service/task/autostart, Supabase/cron write, production network listener, Quick routing modification or PR merge.
- This is a direct real CLI **OFF-only** host binding. A future production Graph enablement is a **different**, exact-SHA/host/profile/percentage/window owner-approved change requiring external release-gate evidence in #275. Do not silently turn a P68 lab permit into production permission.
