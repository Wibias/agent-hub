# P68: durable owner-scoped OFF state + real HTTPS server-host wiring

**Draft only. No production Graph activation, no release approval, no deployment.**

## Concrete infrastructure, not a new audit framework

The repository has no deployed Standard/Deep HTTP host. P65 / P66 proved local canary selection; P67 added a signed shared-state client but no actual state service. P68 connects the **existing P67 client** to a minimal HTTPS coordinator with a durable one-way OFF marker and an explicit trusted server-host factory.

Files:
- `p68-durable-https-coordinator.mjs`: `createP68DurableCoordinatorStore` and `startP68LoopbackCoordinator`.
- `p68-server-host.mjs`: `createP68TrustedServerHost` composes P67's existing HTTPS reader and Standard/Deep runtime adapter.
- `tests/reference-graph/p68-durable-https-coordinator.test.mjs` and one separate child-worker fixture.

## Release and safety boundary

- **Default OFF** when no approved permit file exists.
- A *single* signed, lab-scoped canary permit can be seeded only in a new empty durable directory. A **separate pre-pinned Ed25519 owner key** validates the permit; the coordinator's own independent response signer is used only for signing fresh nonce-bound P67 state replies.
- The permit is tied to exact checkout SHA and dedicated project, Standard/Deep only, at most 5%, up to 10 minutes, and `mode='isolated-integration-canary'`, `default_off=true`, `production_route_wiring=false`. This is **not a production owner authorization**. No key/grant is minted by production code.
- OFF is an exclusive, fsynced file. Once present, `seedSignedLabCanary` refuses to rearm; a restarted coordinator always reads OFF. A crash after writing OFF but before finishing the file system sync fails closed; it does **not** justify claiming cross-host crash durability without the filesystem/OS guarantee.
- The HTTPS server listens **only on 127.0.0.1** using externally supplied TLS credentials, TLS 1.3, authenticated bearer and a single `GET /state` endpoint with a fresh 128-bit nonce. No GET body, redirect, public listener, mutation endpoint, key generation or direct Graph activation. A new signed reply has a 3-second lifetime.
- Worker trust is the separately provisioned response signer public key+pin. `createP68TrustedServerHost` delegates to the existing P67 validator, P40 witness validation, P30 read-only GET, complete P66 Graph-vs-Legacy public JSON parity, and P11 once-only usage semantics. Quick and existing public CLI routing are untouched.
- **The durable OFF directory is one-host storage.** Two independent OS processes can fetch from the same coordinator and see revocation, but the test does not prove multi-host failover, durable distributed transactions, fence-before-response atomicity or a production rollback. Local administrators able to replace directory contents or keys are outside this proof.
- This is a **test-only topology**, not a production-ready external endpoint. To distribute over hosts, first identify the actual trusted host, provision owner-approved signer/key rotation, persistent storage and private TLS/mTLS transport, and measure service-level revoke latency. Do not proxy the test loopback server to a public interface.
- Test signer, owner keys and self-signed TLS certificates are ephemeral and live only in test memory/temp directories. They are not deployment credentials.

## Focused acceptance

Run `node --test tests/reference-graph/p68-durable-https-coordinator.test.mjs`.

The tests use real TLS loopback sockets and two **separate child Node processes** (not just mock worker instances), verify signed P67 challenge responses, reject invalid owner grants/HTTP authentication, assert selected Graph response and Legacy fallback through the P67 host wrapper, exercise durable revoke and service restart, coordinator loss, and corrupt on-disk state fail-closed. The P30 candidate transport in these tests is **mocked**; this is not another live Supabase soak.
