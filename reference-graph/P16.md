# P16 durable grant consumption

P16 makes the P15 one-shot grant-consumption boundary durable on the dedicated Reference Graph Supabase project `vrznfnxzlxaavpqbzbzd` (`agent-hub-reference-graph`, `eu-central-1`).

## What P16 owns

P16 adds an atomic replay ledger in the private `reference_graph` schema and one `service_role`-only RPC:

- ledger: `reference_graph.activation_grant_consumptions_p16`
- RPC: `public.reference_graph_consume_activation_grant_nonce_p16(text,text,text,text)`

The nonce primary key is the serialization point. Concurrent first-use attempts for one nonce can produce at most one successful insert. The successful caller receives a generated `consumption_id`; every replay receives exactly `consumed=false` and `consumption_id=null`.

The ledger stores only the nonce, grant payload hash, request hash, authority hash, generated consumption id, and consumption timestamp. It stores no raw grant, signature, private key, public key, credential, or caller authorization claim.

`anon` and `authenticated` cannot execute the consume RPC. The `service_role` can execute only the RPC and has no direct SELECT or INSERT access to the private ledger.

Consumption is irreversible. There is no reset, delete, unconsume, replay bypass, or administrative retry endpoint. After a nonce has been consumed, P15 requires a newly signed grant for any retry.

## Live deployment rule

Migration `010_reference_graph_activation_grant_consumption.sql` may be applied only to the already-bound project `vrznfnxzlxaavpqbzbzd` after the exact repository implementation SHA passes permanent governance.

The live production ledger must start empty. **Do not consume a synthetic nonce on the live ledger.** Atomic first-use/replay behavior is proven in disposable CI PostgreSQL, including concurrent calls. Live verification is structure- and privilege-only until a real externally signed production grant exists.

## Production state after P16

P16 does not activate the Reference Graph. The expected durable state after successful live deployment is still:

- authority state: awaiting external enrollment
- grant state: not issued
- grant consumed: false
- activation authorized: false
- `activation_performed=false`
- repository default graph enabled: false
- production source: `legacy-control`

P16 also does not mutate `REFERENCE_GRAPH_QUICK_RUNTIME`, deploy an application, or guess a hosting provider.

## P17 boundary

P17 owns the real host/deployment/environment actuator for `REFERENCE_GRAPH_QUICK_RUNTIME` and the corresponding live `readActivationState`, `applyActivation`, `probeRuntime`, and `rollbackActivation` wiring.

Until that real host control plane is identified and bound, production remains `legacy-control` even when the P16 replay ledger is live and ready.
