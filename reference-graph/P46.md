# P46: signed short-lived lab leases for distributed shadow rehearsal

P45's host-local OFF marker is not a cross-host revocation system. P46 adds a **separate, review-only, fail-closed signed lease client** for independent simulated workers, without changing production P11 or creating a remote lease backend.

`evaluateP46SignedLabLease` checks the exact Ed25519-signed bytes, a separately supplied/pinned public-key fingerprint, repository SHA, dedicated project, lab identity, Standard+Deep scope, monotonic sequence and at most **10-second** validity. Revocations must be signed; any missing, expired, wrong-project, wrong-commit, stale-sequence or invalid-signature state blocks. This proof is **not** a trust-anchor attestation, nor a release grant.

`createP46DistributedLabShadowGate` is **lab-only** and requires `mode='isolated-shadow-rehearsal'`, `default_off=true`, `production_route_wiring=false`. Each shadow probe rechecks signed coordinator state before starting, polls during work, and checks once more before accepting an exact result. A timeout, network partition, remote revocation, rollback in sequence, missing response or probe mismatch permanently aborts that worker's active probes and latches it off. A worker restart must be governed by a separately trusted durable revocation backend; this module alone does NOT provide one.

Two independent gate instances can read a common injected coordinator for local tests. No production URL, service-role key, Supabase migration, release authority, cross-host deployment, request usage write, production routing import or Graph activation is added.

**Key limitations:** The injected coordinator transport and signer trust are **not provisioned**; the caller can spoof its own key fingerprint. A previously signed 10-second permit is replayable within its expiry if the coordinator is compromised. A read-before-probe and polling loop are **not an atomic distributed fence**. An in-memory latch is reset by a process restart. Before production require independently pinned signer trust, durable backend with monotonic sequence/nonce and revocation, authenticated server access, a read-only adapter, partition/multi-worker/container tests, operational latency budgets, and a production-like rollback rehearsal with a fresh owner release decision.

**All outputs retain** `activation_authorized=false`, `repository_default_graph_enabled=false`. Original P11/query/P35 pins unchanged. Track real release gates in #275.
