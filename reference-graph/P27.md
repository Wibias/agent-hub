# P27: Standard/Deep legacy baseline (offline, read-only)

**Status:** verification-only implementation; NO-GO for repository-default Graph.  
**Reference date:** explicit UTC date supplied by the operator, not implicit wall clock.  
**Baseline:** pinned current `main` before P27 changes: `313c5504aee23569d4ce3acab78cfffb9fa60e53`.

## Why this exists

P25/P26 proved the Quick-only Graph path and its frozen stability evidence.
They did not prove Graph readiness for Standard or Deep. P10's projection,
P7's graph selection policy and P11's production routing are Quick-only.

The production query's omitted `--profile` resolves to `standard`,
not `quick`. Promoting Quick to a repository-wide default would silently
reduce the sample limit (Standard defaults to 12; Quick defaults to 4)
and change coverage requirements. This is explicitly forbidden by P26.

P27 first pins the **unchanged legacy Standard/Deep output behavior** over
the existing 24 canonical Quick scenario templates. It changes only the
*offline evaluation request's profile and limit*, not the source records,
patterns, benchmark source, production entrypoint, or routing mode.

## What P27 produces

For every source scenario, evaluate both `standard` (default limit 12)
and `deep` (default limit 28) at the same reference date.

Each result includes the source case ID, profile, request limit, selected
record/pattern counts, structural coverage-gap kinds, and SHA-256 digests
of the **ordered** selected record and pattern IDs. These hashes are
deterministic baseline fingerprints and do not certify visual relevance,
graph parity or improved retrieval quality.

Top-level summary: source case count, total profile cases, assessed/complete/
gap counts for Standard and Deep, reference date, explicit
`repository_default_graph_enabled=false` and `activation_performed=false`.

No Graph API calls, credentials, live state writes, usage logs, database
mutations, scheduler changes, new grants or production configuration.

private catalog contents or environment variables into PR comments.

## Verification boundaries and next requirements

- Regression tests require exact legacy record/pattern hashes, deterministic
  case ordering, correct profile limits, no mutable template input, and
  rejection of malformed/extra CLI arguments.
- **This report is only a historical legacy-control baseline.** A future
  Graph Standard/Deep candidate must independently implement profile-specific
  coverage, pattern parity, current-date candidate eligibility, latency
  budget and explicit fallback. It must be evaluated against fresh baselines.
- No claim of parity, real-user quality improvement, or production rollout
  may be derived from P27's read-only hashes alone.
- Before default promotion, implement a separate default-off authority,
  externally approved scope, rollback proof and post-change health receipt.
  The P19 evaluator cannot certify a default-on state.
- #223 and #225 are distinct prior release-readiness and archive verification
  PRs; this P27 PR does not depend on merging them to execute safely.

**No merge or production activation without an independent review.**
