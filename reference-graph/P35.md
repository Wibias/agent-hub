## Exactly what P35 does

`reference-graph/p35-pr-stack-lock.json` freezes the ten relevant upstream PR numbers, **exact head and base commit SHA-1**, base branch names, the expected thirteen CI workflow names, and the dedicated target identity `vrznfnxzlxaavpqbzbzd`. It keeps the two P26 review threads **independent** from the eight-PR Standard/Deep stack. It does not attempt to collapse #223 or #225 into the stacked branch history.

`reference-graph/p35-release-preflight.mjs` is an offline, fail-closed evaluator of a *separately collected* GitHub/Supabase-inventory snapshot. It validates:

1. Exact lock schema and uninterrupted P27-P34 branch/commit ancestry, including the independently pinned P26 reviews.
2. Ten unique GitHub PRs corresponding exactly to the lock (no unexpected or missing PRs), their current head/base SHA, branch and open/closed/merged/draft states.
3. Each PR's exact set of **13 completed successful workflows on its locked HEAD**, not simply green CI on another commit or another branch.
4. The latest **controlling** review disposition (`APPROVED`, `CHANGES_REQUESTED`, `DISMISSED`) from each independent reviewer on the exact head SHA. A later `COMMENTED` is not a new approval and **cannot** cancel an outstanding `CHANGES_REQUESTED` or a previous approval. GitHub logins are validated and compared case-insensitively: author self-review, dismissed approval, changed head or outstanding changes requested blocks the gate.
5. **Zero unresolved review threads** and no draft/closed-but-unmerged PRs.
6. A bounded-freshness (15-minute), explicitly clocked input snapshot and a supplied Supabase project inventory containing the dedicated reference-graph target ref.

The ten upstream PRs are the input matrix. **P35 PR #234 itself is not in its own lock and must be separately reviewed and approved by a different person.** Updating P35 does not create or satisfy a GitHub review.

Only the local code-review **subgate** can report `review_gate_satisfied: true`. Supplied JSON/sha256 is not evidence that GitHub or Supabase originally produced the records. The receipt always reports:

```json
{
  "github_snapshot_independently_attested": false,
  "target_access_authorized": false,
  "live_graph_parity_verified": false,
  "deployment_authorized": false,
  "activation_authorized": false,
  "repository_default_graph_enabled": false
}
```

A project ref's presence in supplied inventory is only a discovery signal. It cannot verify permissions, current database schema, Data API settings, RLS policies, publication status or migration authorization. In the current connection only the separate **Streamer Content** project is visible; the dedicated AgentHub reference-graph target is not.

## Input contract

An independent operator exports or collects a **read-only** evidence file with two keys:

```json
{
  "githubSnapshot": {
    "schema_version": "reference-graph.p35-github-snapshot.v1",
    "repository": "Wibias/agent-hub",
    "observed_at": "2026-11-07T19:00:00.000Z",
    "prs": []
  },
  "projectInventory": {
    "schema_version": "reference-graph.p35-project-inventory.v1",
    "observed_at": "2026-11-07T19:00:00.000Z",
    "project_refs": []
  }
}
```

The empty arrays above describe **only the envelope shape**, not a passing input. Provide **all ten** full GitHub snapshots with their current `number, head_sha, base_branch, base_sha, author, state, merged, draft, unresolved_review_threads, reviews, workflows`. Each review has `reviewer, state, commit_sha, submitted_at`. Each workflow has `name, head_sha, conclusion`. Obtain actual review submission state and unresolved-thread counts from GitHub rather than assuming zero. The project inventory contains only project refs. Never insert a Supabase API key, GitHub token, private catalog, candidate rows or credentials into this file.

Compute the exact SHA-256 of the evidence bytes **outside the P35 evaluator**. Preserve the file and digest in a separately trusted, access-controlled archive. The evaluator checks byte consistency, but cannot establish the archive's independent provenance.

### Offline read-only command

From a separately pinned P35 checkout (with reviewed SHA and clean working tree), execute:

```powershell
node reference-graph/cli/p35-release-preflight.mjs --evidence "C:\\audit\\p35-evidence.json" --sha256 "<externally-recorded-64-hex-digest>" --as-of "2026-11-07T19:05:00.000Z"
```

Replace the example clock with the current, explicit UTC `--as-of`. The file's GitHub and inventory timestamps must be within 15 minutes and not later than `--as-of`. The P35 CLI performs **no network calls, no writes, no key access and no Supabase operations**. It emits an aggregate, redacted JSON report to stdout.

Exit statuses: **1** = malformed/stale/mismatched input (no stdout); **2** = valid evidence analyzed, but **release remains blocked**. The CLI intentionally cannot return a deploy-authorizing success code. A fully reviewed and merged *synthetic* input still exits 2.
