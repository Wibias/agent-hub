# Reference Graph P15 — Grant-Gated Activation Executor

P15 defines the provider-neutral execution boundary for a real production activation. It does not enroll a production authority, create or sign a grant, or expose a repository command that mutates production. The committed operator remains read-only; the actual deployment/environment mutation is performed only through an externally supplied actuator implementation.

## Frozen authority boundary

P15 is bound to the final P14 evidence head `43fd2adf9e73749b03283f7ae7c6e700bd383b35` and the exact P14 evidence bytes SHA-256 `610f9f832d994e565fe6912e3aa1e25d5fe5b549fa08f1a48f477ee9b3956393`.

The P14 Ed25519 verifier remains the sole grant authority. P15 does not add another trust path, production signer, private-key parser, key generator, or embedded production authority.

## One-shot activation sequence

A production attempt is single-use and fail-closed:

1. Re-verify the externally signed P14 grant at the current time.
2. Read production state and require `legacy-control`, Quick graph disabled, and the repository default still graph-off.
3. Atomically consume the grant nonce before the first production mutation.
4. Re-verify the same grant immediately after nonce consumption and before mutation.
5. Ask the external actuator to apply only `REFERENCE_GRAPH_QUICK_RUNTIME=graph`.
6. Probe live runtime behavior. Quick must report `reference-graph` with exact ordered record and pattern parity. Standard and Deep must remain `legacy-control`.
7. If apply or verification is ambiguous or fails, ask the external actuator to roll back and then live-probe the restored legacy route.

Once nonce consumption succeeds, the grant is spent permanently. Any retry after an expired post-consumption grant, failed activation, failed probe, rollback, or unverified rollback requires a new externally signed grant. Reusing the consumed grant is not permitted.

## External actuator contract

The repository core accepts injected callbacks for reading activation state, atomically consuming a nonce, applying the Quick-only activation, probing runtime behavior, and rolling back. This keeps P15 provider-neutral: there is **no provider-specific mutation implementation** in the repository and no assumption about which deployment platform owns the production environment variable.

The nonce-consumption implementation must be durable and atomic in the real production control plane. The apply and rollback implementations must return auditable change identifiers. Those mechanisms are external production infrastructure; P15 validates their outcomes but does not invent or silently substitute them.

## Profile and fallback boundary

Only the Quick profile may switch to graph authority. Standard and Deep stay `legacy-control` throughout P15. The repository default remains graph-off, and P11 still fails closed to the legacy selector whenever graph transport or exact handoff parity fails.

A successful P15 activation therefore changes the live Quick source only after grant authorization and post-switch verification. It does not make graph routing the repository default.

## Read-only repository operator

`reference-graph/cli/p15-activation-executor.mjs` intentionally exposes only repository inspection:

- `--plan` describes the frozen activation boundary.
- `--verify-repository` verifies the P14 byte binding, graph-off default, absence of migration 010+, and the absence of production signing or provider mutation paths in P15.

It provides no production mutation command. A real activation requires all of the following outside the read-only operator: an enrolled external production Ed25519 authority, a currently valid signed grant, durable one-shot nonce consumption, and an externally wired production actuator.

## Current durable state

Until those external artifacts and controls are supplied, P15 remains blocked from actual production activation: no production authority or grant is fabricated, `activation_authorized=false`, `activation_performed=false`, the repository default remains graph-off, and production remains `legacy-control`.
