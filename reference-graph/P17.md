# Reference Graph P17 — Local Runtime Actuator

P17 binds the P15 activation executor and the P16 durable one-shot grant ledger to the real local AgentHub runtime without inventing a server deployment provider.

## Control plane

The production design-reference path is the local AgentHub checkout under `~/.agents` (or an equivalent `AGENTS_HOME` / `USERPROFILE`-resolved agent home). The documented query command now enters through:

```text
node knowledge/design-references/scripts/query-runtime.mjs ...
```

`query-runtime.mjs` does not replace P11. It projects local P17 activation state into the existing P11 contract and then starts the unchanged `query.mjs` child. The only graph activation value remains exactly:

```text
REFERENCE_GRAPH_QUICK_RUNTIME=graph
```

Quick may become Reference Graph authoritative only when the P11 exact-record and exact-pattern checks pass. Standard and Deep remain `legacy-control` even when the durable P17 state is graph.

## Local activation state

Mutable state is outside the Git checkout:

- Windows: `%LOCALAPPDATA%/agent-hub/reference-graph/activation-state-v1.json`
- POSIX: `${XDG_STATE_HOME:-~/.local/state}/agent-hub/reference-graph/activation-state-v1.json`
- Test/operator override: `AGENT_HUB_REFERENCE_GRAPH_STATE`

Missing, malformed, wrong-schema, or extra-key state fails closed to `legacy-control`. An apply or rollback writes a complete same-directory temporary file and completes the change with an atomic rename. No partial graph state is treated as activated.

The state contains only the P17 schema, mode, change ID, P16 consumption ID, grant-payload hash, and update time. It contains no raw grant, signature, credential, authorization boolean, signer, or private key.

## Activation ordering

A real activation remains controlled by P15. P17 only supplies the concrete callbacks.

The order is deliberately unchanged:

1. P15 verifies the external Ed25519 signed activation grant.
2. P15 requires a valid `legacy-control` pre-state.
3. P16 consumes the grant nonce irreversibly **before any local activation mutation or apply**.
4. P15 re-verifies the grant at a fresh time.
5. P17 atomically applies local graph state.
6. P17 probes the same projected runtime path: Quick must be Reference Graph exact; Standard and Deep must remain `legacy-control`.
7. Any failed post-mutation verification invokes atomic rollback and requires a second probe proving restored legacy behavior.

A consumed grant is never retried. A failed activation or verified rollback therefore requires a new externally signed grant.

## Why this does not use persistent process environment

P17 does not globally mutate the Windows user environment and does not rely on restarting or relaunching an already-running Codex/OpenCodex parent. Existing parent processes can retain stale inherited environment. Instead, the wrapper projects the durable P17 state immediately into each future `query.mjs` child process.

A global restart is **not required** for the P17 projection contract.

## Probe boundary

The public `query.mjs` output remains unchanged and does not expose routing metadata. P17 therefore derives the exact same state-to-environment projection as `query-runtime.mjs` and invokes the existing P11 router directly for activation verification.

The production probe uses only the P10 publishable runtime transport for Quick when graph mode is projected. It does not introduce a service-role runtime read path. Standard and Deep remain zero-network legacy routes under P11.

## CI safety boundary

The `Reference graph P17 governance` workflow uses a disposable temporary `AGENT_HUB_REFERENCE_GRAPH_STATE`. CI may exercise synthetic local state and ephemeral test grants inside tests, but it does not call the live P16 consume RPC, does not consume a live nonce, does not use production credentials, and does not execute production activation.

P17 owns no migration 011 or later. P16 remains the durable replay ledger boundary.

## Current production state

P17 makes the local host actuator implementation ready, but it does **not** create an external authority, signer, private key, or production grant.

Until a real independently enrolled Ed25519 authority supplies a valid externally signed activation grant and the production operator deliberately executes it:

- production remains `legacy-control`;
- `grant_consumed=false`;
- `activation_performed=false`;
- repository default graph activation remains false;
- no live nonce has been consumed by P17 CI or this implementation phase.

The remaining blocker is the real external Ed25519 authority/grant ceremony. P17 must not fabricate that authority or grant merely to test activation.
