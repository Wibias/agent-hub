# P49: isolated mTLS coordinator adapter (release NO-GO)

P48 established an authenticated, persistent-state *loopback* coordinator with no production activation. P49 is a separate **mTLS HTTPS adapter** suitable for isolated network test deployment only.

- `startP49MtlsLabCoordinator` serves **GET /state** over TLS 1.3 with a required client certificate signed by the supplied lab CA, plus an **exact SHA256 pin of the permitted client's leaf DER certificate**. It reads the P47 signed durable state on every request. Invalid/revoked/partial/expired state returns generic 503. No mutating HTTP routes, signing key, candidate data, service-role key or production import.
- By default it only binds to `127.0.0.1`. Binding `0.0.0.0` requires an explicit `isolatedContainerNetwork: true` option. This flag is NOT a security boundary. An actual Docker deployment must use an internal-only network with no published host ports.
- `readP49MtlsSignedState` additionally checks the server certificate chain, name/SAN, SHA256 leaf pin, TLS 1.3 and deadline. Workers still validate the independent Ed25519 P46 signed lease, scope, commit, expiry and sequence. A TLS certificate does not grant a Graph route.
- Ephemeral test CA/server/client certificates are created during tests via OpenSSL. Private TLS keys, the state signer key and auth tokens must **never** be committed or copied to production. Tests exercise valid mutual authentication, wrong client, wrong CA, wrong server identity, invalid pin, unsigned/corrupt persistent state, revocation and network failure.

**Not a production environment:** Neither globally trusted certificate issuance nor a separately audited signer has been deployed. A TLS-protected state GET does not atomically fence an in-flight Graph query from an asynchronous revoke. P47 is still a single-host file journal. Multi-host failover, nonce ledger, independent attestation, latency/error/quality gates, a P11 Standard/Deep production adapter and a real rollback rehearsal are still OPEN in #275.

P11, query.mjs, pinned P33 and historical P35 are unchanged. PR #276 remains Draft. `activation_authorized=false` unconditionally.


## P49 isolated multi-container mTLS rehearsal (GitHub CI)

The `reference-graph/cli/p49-rehearse-isolated-containers.mjs --isolated-test` command runs only when `P49_ALLOW_DOCKER_REHEARSAL=1` is set. Its GitHub workflow step is separate from the existing disposable P32/PostgREST tests.

It generates **fresh ephemeral OpenSSL CA, server and two client certificates**, plus an **ephemeral independent Ed25519 lab signer**. The signer private key remains in the host Node process and is **never mounted in a container**. The state directory contains only signed P46 permit/revocation envelopes and P47 OFF intent. All files are deleted at the end.

The harness creates a unique **Docker internal bridge** with **zero published host ports** and runs the coordinator and at least two separately started worker containers, all with a read-only root filesystem, dropped Linux capabilities and no-new-privileges. The coordinator gets only server TLS key, CA, P47 read-only state, public signer key and a public identity manifest. Workers get only their own client TLS private key, CA and public signer identity; they cannot access the coordinator key, P47 journal or signer private key.

**Checks:** two lab workers accept independently validated short-lived signed permits; a third worker with a different leaf certificate signed by the SAME CA is rejected by its client pin; a pending worker receives revocation and aborts; restart of the coordinator does not replay its pre-revoke permit; total coordinator connection loss blocks workers. No actual Graph result is ever selected, public output remains Legacy, and no usage data is written.

A successful Docker run proves **separate isolated container network namespaces on one Docker host**, not an independently authenticated multi-host production deployment. The certificate authority and signer are disposable and self-issued for tests; there is no globally governed production trust anchor or distributed transactional fence. The `node:24-alpine` Docker image used is CI-only and must be immutably pinned and supply-chain reviewed before any production use.

No Supabase/API keys, publication, app routing, GitHub secret provisioning, Windows automation or Graph activation occur. P49 Docker PASS cannot grant a #276 merge, owner activation, release attestation or productive rollback.


## Additional P49 safety regressions

The original coordinator-loss scenario ran **after** a signed revocation, which did not independently prove fail-closed behavior during a still-valid permit. The updated Docker rehearsal stops the coordinator while an unrevoked permit is valid and a worker is **already probing**. It asserts immediate cancellation; a fresh worker launched while the coordinator is offline must also be blocked. After restoring the coordinator, a new lab-only worker must regain eligibility with the same valid signed lease, demonstrating the failure was due to transport loss rather than a revoked permit. The original in-flight signed-revocation and restart tests remain in place.

A separate expired-lease worker independently advances its verifier clock and must reject a cryptographically valid but expired lease before attempting a probe.

The runner also resolves `node:24-alpine` to an OCI SHA256 manifest digest immediately after pull and uses that **exact image reference for all containers in one run**, recording only the public digest and an explicit `runtime_image_reviewed_pin:false` flag. This closes an image-tag time-of-check/time-of-use ambiguity *within that run*; the original input tag is still mutable. A reviewed, fixed digest in CI and container supply-chain approval are still required before production. The test does not represent a multi-host deployment.
