# P12 activation authority preflight

P12 separates **technical readiness** from execution authority.

The read-only activation preflight binds the final P11 evidence head, tested P11 implementation, dedicated Supabase target, current projection snapshot, production query/router hashes, publishable-only runtime contract, exact ordered record/pattern parity requirements, the 1500 ms timeout, and the fail-closed rollback rule into one deterministic `binding_hash`.

A successful P12 receipt may report `preflight_ready: true`. That still does **not** switch normal production traffic and does not create a deployment grant. P12 permanently records `grant_state: not-issued`, `activation_authorized: false`, `activation_performed: false`, `repository_default_graph_enabled: false`, and `production_source: legacy-control`.

The P12 operator is read-only. It can print the expected activation binding, verify repository hashes, and finalize an externally gathered secret-free live snapshot. It cannot refresh the P10 projection, mutate database state, change environment configuration, deploy, or activate routing.

Quick remains default-off. Standard and deep remain legacy-only with zero graph network calls. A stale projection fails the current-date preflight; P12 does not refresh it to manufacture readiness.

P12 adds no schema migration after `009_reference_graph_runtime_projection.sql`.

Any later production activation requires **separate explicit operator/deployment authority** that references the exact P12 `binding_hash`. Until that later authority exists, the production source remains the legacy control.
