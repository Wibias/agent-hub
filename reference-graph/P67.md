# P67: trusted server-side Standard/Deep opt-in with shared OFF state

**Code only, default OFF. Production Graph activation: NO-GO.**

## Why this is not another lab soak

The AgentHub repository currently has a local design-reference query CLI, not a deployable Standard/Deep HTTP server. The existing public entry points `knowledge/design-references/scripts/query.mjs` and `reference-graph/p11-runtime-router.mjs` remain untouched. P65 and P66 are disconnected Draft implementations.

P67 introduces one **server-host-facing runtime adapter** that can return a genuine P30/Graph-built Standard/Deep response only if a separately provisioned *trusted central coordinator* permits that exact request. This creates the missing integration contract. It does **not** invent a production server or claim that a central coordinator has been deployed.

## Server wiring contract

A trusted server host calls `createP67ServerProfileAdapter()` once per worker, then `run()` for an authenticated Standard/Deep request. The host supplies:

- Exact deployed repository SHA (40 hex), fixed project `vrznfnxzlxaavpqbzbzd`.
- An Ed25519 public key **and separately operator-pinned SHA-256 SPKI fingerprint**, provisioned as trusted server configuration, never from an HTTP request.
- `readSharedState({nonce,signal})`, which reads the **same durable coordinator** for all workers. `createP67HttpsStateReader()` provides a GET-only HTTPS adapter with a server-held read token, no redirect, no caching, bounded timeout and an unpredictable 128-bit nonce challenge.
- Current P40 witness JSON plus pinned SHA-256 via `getWitness()`. The P40 validator enforces project, candidate membership/metadata consistency, refresh instant, snapshot date and freshness.
- An exclusively server-held `sb_secret_` credential, bounded P30 read-only transport, trusted source catalog, a server-derived stable cohort key (not user-submitted) and a server-owned clock.
- Optional authentic P11 usage recording; P11 runs **once**, not on every retry or fallback. New code never performs a direct usage write.

**State envelope** (the coordinator must sign the UTF-8 bytes of `payload_json` with the pinned Ed25519 private key):

```json
{
  "payload_json": "{...canonical signed state...}",
  "signature_base64": "<Ed25519 detached signature>"
}
```

Signed state requires exactly these fields: `schema_version='reference-graph.p67-shared-state.v1'`, `repository_sha`, `project_ref`, `nonce` (echo of the 128-bit challenge), positive integer `generation`, `status='off'|'canary'`, `profiles` (Standard/Deep only), `canary_percent` (0 when OFF, 1-5 when canary), `cohort_salt` (32 lowercase hex), `issued_at`, `expires_at` (canonical UTC ISO). Signature, key pin, current nonce, exact repo SHA/project, issued age <=5 s, maximum 10 s permit lifetime and strictly monotonic per-process generation floor are verified before any Graph GET. Each verification is a fresh challenge, so a previously captured envelope cannot be replayed for a different request.

All workers fetch live shared state **before selection**, poll while selected Graph work runs and require a second fresh signed check **after** complete public JSON comparison and before Graph return. A central OFF state, expired/unreachable/invalid signer, changed generation, network failure, stale P40 source, P30 error, timeout, or complete JSON mismatch causes Legacy fallback and (for operational failures) a latched per-process OFF state. If the fetch adapter ignores AbortSignal, an independent cancellation promise rejects before its late result can be returned.

## Critical release limits

- **Not wired or deployed.** P67 provides a callable server adapter, not a new public network listener. There is no production Standard/Deep server or separately approved coordinator in this repo. No `REFERENCE_GRAPH_STANDARD_RUNTIME` flag, no GitHub PR merge authority, no DB/cron modification, no Windows task change.
- The coordinator's durable state, atomic generation increments, trusted signing key, authentication, operator identity and owner release process must be **supplied and validated outside this PR**. The constructor's injected trust-key fingerprint alone is not independent review. A coordinator may sign permits only after the owner explicitly approves an exact version and scope.
- The state read is per request, not a cryptographically atomic read/write fence with the final HTTP response. A revocation between the final signed state check and sending a response remains a bounded race; a real multi-host roll-out requires a measured service-level revoke/latency budget and documented residual risk. No claim of a proven atomic fence.
- A process restart clears only the local latch. **The coordinator must persist revocation** and return OFF for every fresh challenge across workers and restarts. Failure to contact the coordinator denies Graph, not Legacy.
- HMAC cohort selection is stable across workers but **requestKey must originate from authenticated host context**. Do not accept arbitrary query/body supplied keys for canary selection.
- This integration only changes the **selection origin**: hydrated record text remains from the unchanged local legacy catalog. It is not a Graph-only content source. Complete output must match P11 byte for byte; otherwise no Graph output.
- It is not evidence of owner approval, an actual external multi-host deployment, production rollback, external state provenance or independent audit. No release gate in #275 is silently closed.

## Focused verification

```sh
node --test tests/reference-graph/p67-server-profile-adapter.test.mjs
```

Tests create ephemeral Ed25519 keys and a shared mutable state provider (test only). They verify the exact signer, nonce, repo/project/scope, stale state and signature failures, two worker instances observing the same revocation and a restarted instance seeing OFF, an in-flight P30 operation that ignores AbortSignal, 5% cohort selection, real Graph output/public JSON parity, a single P11 usage call, and the protected HTTPS reader contract.
