# P66: isolated production-like Standard/Deep Canary and real local rollback

**Draft / NO-GO for production release.** This increment is stacked on P65 Draft #281 and does not modify P11, the public CLI, Quick, existing service endpoints, Supabase, cron, Windows tasks or usage logs.

## What changes from P65 shadow

- P65 always returns Legacy. **P66 actually returns a separate public object constructed from P30 Graph-selected candidate IDs** when an eligible isolated rehearsal request is an exact match against the authentic P11 Legacy public JSON.
- `p66-graph-public-output.mjs` implements the reviewed P34-style reconstruction for **one request**: validated P29 candidate selection, local record hydration and freshness, selection scores, diversity penalties, stratified coverage, gaps and independently ranked patterns. It does **not** call P11 or the Legacy selectors. A separate test compares the complete reconstructed public outputs across all 48 Standard/Deep control cases.
- `p66-isolated-canary-rehearsal.mjs` performs a genuine P30 server-only bounded GET using the existing validated P40 witness and exact dedicated project, builds the Graph public response and compares its **entire JSON** against the fresh authentic P11 response before permitting local Graph authority.
- No secret, input catalog, request text or candidate row is emitted by diagnostics; secrets are supplied only in the trusted server process and never read from an environment variable or command argument.
- If output/parity differs, source/witness is invalid, HTTP fails, a deadline fires or an operator revokes the instance, P44 aborts in-flight calls, latches future Graph attempts OFF and returns Legacy. A process restart defaults OFF.
- Deterministic stable request-key cohort selection is limited to 1-5% for testing, never inferred from browser state. Non-selected requests produce Legacy without a protected GET.
- A local rehearsal result may report `routing.authoritative_source='reference-graph'`, meaning **only that isolated Graph-built output was chosen**, NOT that the production route was activated. The live P11 route remains disconnected.

## Explicit limitations

1. **This is not a deployment, live opt-in, a production Canary, a release authority or a real production rollback rehearsal.** Scope `mode='isolated-production-like-canary-rehearsal'`, exact checkout SHA, project, profiles, `default_off=true`, `production_route_wiring=false` and a 1-5% cohort are mandatory.
2. Caller-controlled scope and cohort key are **test controls**, not authenticated owner approval. A production canary still needs verified server identity, signed scoped owner grant, durable cross-worker fencing/revocation, nonce/sequence protection and monitors. Do not wire P66 into P11 or publish its service key.
3. This validates **Graph selection over verified server P30 candidates**, hydrated into the existing local source catalog. It does not establish that Graph is an independent source of record text. Exact full public JSON parity is a mandatory gate before release.
4. P44's OFF latch is process-local, not a multi-host guarantee. In-flight abort depends on the underlying transport honoring AbortSignal. A final P44 latch check blocks late responses from becoming authoritative.
5. Rehearsals deliberately disable usage recording and cannot prove exactly-once production usage or capacity. P64 24h and P40 48/48 observations are distinct prior evidence, not a replacement for a production-like measured rollback.
