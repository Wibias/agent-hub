# P13 Activation Grant Authority

P13 adds a fail-closed, verify-only activation grant authority boundary on top of the final P12 evidence head `5f676c806ae864b507723ea867f5e3afd6fd4adb` and exact P12 activation binding hash `68930447847df8d31de01b7fb60049136ae6fd0d74c837283fb837ff7e79961b`.

P13 does not activate Reference Graph routing. It does not enroll a production authority, issue a production grant, generate or store a private key, mutate deployment configuration, set `REFERENCE_GRAPH_QUICK_RUNTIME`, call Supabase, refresh the runtime projection, add DDL, or send normal-user traffic through the graph.

## Authority model

A P13 grant request is deterministically bound to:

- the final P12 evidence head;
- the exact P12 `binding_hash`;
- SHA-256 of the committed P12 evidence bytes;
- the dedicated P12 target;
- quick-only scope;
- `REFERENCE_GRAPH_QUICK_RUNTIME=graph` as the later opt-in value;
- publishable-only runtime auth;
- the `1500 ms` timeout;
- legacy-first selection;
- exact ordered record and pattern parity;
- fail-closed fallback to `legacy-control`;
- standard/deep legacy-only isolation;
- repository graph default off;
- rollback by unsetting or changing `REFERENCE_GRAPH_QUICK_RUNTIME`.

The authority descriptor contains only an Ed25519 public key plus authority/key identifiers. It is not trusted by itself. Verification requires an independently supplied external trust anchor, `trusted_authority_sha256`, equal to the canonical authority descriptor SHA-256. Missing or mismatched trusted authority data fails closed even when the supplied signature is otherwise cryptographically valid.

The repository intentionally contains no enrolled production authority descriptor. Production state therefore remains:

```text
authority_state: unconfigured
trusted_authority_sha256: null
grant_state: not-issued
grant_verified: false
activation_authorized: false
activation_performed: false
repository_default_graph_enabled: false
production_source: legacy-control
```

## Grant validity

A signed grant must match the exact request hash, P12 evidence head, P12 binding hash, target, profile, activation flag/value, issuer and key ID. It uses Ed25519 and a 32-byte nonce encoded as lowercase hex.

`issued_at <= not_before <= now <= expires_at` must hold. The full grant lifetime is at most 15 minutes. Future, expired, malformed, overlong, wrong-scope, wrong-authority, wrong-binding, or invalid-signature grants fail closed.

A successful signature verification only means `grant_verified: true` for the caller-supplied grant and trust anchor. The operator still returns `activation_authorized: false` and performs no activation.

## Read-only operator

The operator is:

```text
node reference-graph/cli/p13-activation-grant-authority.mjs --plan
node reference-graph/cli/p13-activation-grant-authority.mjs --emit-request
node reference-graph/cli/p13-activation-grant-authority.mjs --verify-repository
node reference-graph/cli/p13-activation-grant-authority.mjs --verify-grant <grant.json> <authority.json> <trusted-authority-sha256> <now-iso>
node reference-graph/cli/p13-activation-grant-authority.mjs --finalize-repository <snapshot.json>
```

`--plan` describes the frozen P12/P13 boundary without network access.

`--emit-request` emits the canonical request and request hash derived from the committed P12 evidence.

`--verify-repository` recomputes the P12 evidence SHA-256, confirms the legacy-default runtime boundary, confirms migration numbering remains below `010`, and checks that P13 contains no signing/private-key, activation mutation, or Supabase mutation path.

`--verify-grant` verifies a caller-supplied Ed25519 grant against a caller-supplied authority descriptor and separate trusted authority SHA-256. It never applies the grant.

`--finalize-repository` creates the P13 infrastructure receipt from repository state plus a tested implementation SHA and timestamps. A successful receipt may have `infrastructure_ready: true` while production authority remains unconfigured and no grant exists.

## Hard stop

P13 ends at auditable grant-verification infrastructure. Even when all P13 tests and governance are green:

- no production authority is enrolled;
- no production grant is issued;
- no activation is authorized;
- no activation is performed;
- repository default stays legacy;
- production source stays `legacy-control`;
- no Supabase mutation occurs.

A later, separate phase must establish the production authority trust anchor and issue a grant bound to the exact P13 request. A further explicit activation phase is still required before any routing change can occur.
